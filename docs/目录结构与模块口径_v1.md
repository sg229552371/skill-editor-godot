# 目录结构与模块口径 v1

> **本文是仓库级口径，管 `mods/` 下的所有模块，不属于任何单个模块。**
> 任何模块的接手者（人或 AI）在新增/移动目录之前，必须先读本文。
>
> 级别：**S1**（与模块内《施工规格》同级；两者冲突时，本文管「在哪里」，模块文档管「怎么做」）
> 裁定：制作人 2026-10-22；两轮修正后定稿（见 §六 修正记录）

---

## 一、一句话口径

**`mods/` 下面，一个目录 = 一个模块。目录名 = `作者-功能`，用户看名字就能猜出这个模块是干什么的。**

没有「作者空间」这一层，没有「功能域」这一层，没有嵌套。`jes` 只是名称前缀，**不是目录**。

```
mods/
├─ jes-skills/       ← 模块：作者 jes，功能 skills（技能系统）
├─ jes-inventory/    ← 模块：作者 jes，功能 inventory（背包系统）
└─ alice-ui/         ← 模块：作者 alice，功能 ui
```

`jes-skills` 与 `alice-ui` **平级是正确的**——两者都是「作者+功能」的模块目录，谁也不属于谁。

## 二、三层结构（唯一合法形态）

```
mods/
│
├─ <作者>-<功能>/           ← 第 1 层：模块（可枚举、可开关、可声明依赖）
│  │
│  ├─ systems/              ← 第 2 层：模块内部结构（模块自己决定，不强制统一）
│  ├─ content/                现有模块用的形态：
│  ├─ tests/                  systems/ content/ tests/ docs/ sandbox/ tools/
│  ├─ docs/
│  └─ tools/
│
└─ <作者>-<功能>/           ← 第 3 层不存在：模块之间不嵌套
```

**关键约束**：

| 约束 | 说明 | 违反后果 |
|---|---|---|
| 模块之间**不嵌套** | 背包是 `mods/jes-inventory/`，**不是** `mods/jes-skills/inventory/` | 技能模块沦为容器，职责混乱；卸载技能会带走背包 |
| 模块名**含作者前缀** | 防止第三方 mod 撞名；也让人一眼看出归属 | 引入第二个作者后出现 `skills` 重名冲突 |
| 模块内部结构**不强制统一** | 技能模块有 `sandbox/`，背包模块可能没有；这是允许的 | 为了"统一"给每个模块塞空目录，是无意义噪音 |
| 第 1 层**必须可枚举** | 加载器、模块注册表以这一层为单位，无需理解内部结构 | 加载器被迫写死路径，等于没有模块化 |

## 四、`_shared/` 的启用条件（暂不建）

**当前不建 `mods/_shared/`。** 建它的唯一条件是：

> 有两个及以上模块**都需要**同一份接口契约（类型定义、事件名、枚举），
> 且这份契约**不属于其中任何一个模块**。

在条件满足之前建 `_shared/`，结果一定是它变成第二个 `util` 垃圾桶——
什么"可能有用"的东西都往里丢，最后没人知道里面哪些是活的。

**启用时的规则**（写在这里，免得临时拍脑袋）：
- `_shared/` 是 `mods/` 下的**保留名**，不是模块，不参与模块枚举
- 只放**契约**（`*.gd` 里的 class_name 声明、枚举、事件常量），**不放实现**
- 每个文件必须有且只有一个消费者以上的明确记录

## 五、命名规则

| 项 | 规则 | 正例 | 反例 |
|---|---|---|---|
| 模块目录 | `<作者>-<功能>`，全小写，连字符分隔 | `jes-skills`、`alice-ui` | `JesSkills`、`jes_skills`、`skills` |
| 作者前缀 | 短、稳定，不随功能变 | `jes` | `jinyishun`（太长）、`me`（无意义） |
| 功能名 | 单数、具体、看得出做什么 | `inventory`、`quest` | `gameplay`、`misc`、`common` |
| 模块内目录 | 模块自定，建议沿用现有形态 | `systems/`、`content/` | 不许出现 `mods/` 下的模块名，避免歧义 |

### 5.1 语言规则（制作人 2026-10-22 裁定）

作者在中国，后续开发者以国人为主。**看这份文件的人是谁，决定它用什么语言。**

| 对象 | 语言 | 理由 |
|---|---|---|
| 文档正文 / 代码注释 / 报错信息 | **中文** | 人机沟通面，必须让国人一眼看懂 |
| commit message 描述部分 | **中文** | 同上（type 前缀保持英文） |
| 面向玩家的文案 | **中文** | 游戏本身面向中文用户 |
| **目录名（代码结构）** | **英文** | 与现有模块一致；跨工具（CI/打包/插件）有隐性风险 |
| `class_name` / 变量 / 函数名 | **英文** | GDScript 惯例；中文标识符会拖累 IDE 补全与全文搜索 |
| 标签 / 枚举值 / 资源路径 | **英文** | 数据键会被机器匹配，改动影响面大 |

> **注意**：Godot 4.7 实测**支持中文路径**（`ResourceLoader.exists` 与 `load()` 均正常），
> 所以这条不是技术限制，而是**一致性选择**——两个模块必须一套规矩，不能各说各话。
> 若以后确需中文目录，必须在本文件登记，并说明哪些工具已验证支持。
>
> 模块内细则见 `mods/jes-inventory/docs/_AI开发与文档/语言使用口径_v1.md`。

## 六、模块内部标准形态（以 jes-skills 为参考）

```
<模块>/
├─ systems/      运行时代码（核心逻辑）
├─ content/      数据真源（.tres 等，新增内容不改代码）
├─ tests/        测试（headless 可跑）
├─ docs/         文档
│  ├─ _AI开发与文档/     ← AI 读写主体（中英文均可，中文优先）
│  ├─ _人工文档流程/     ← 人机决策档案（AI 默认不读）
│  └─ _重要资料记录/     ← 只查不写的外部参考
├─ sandbox/      可选：可视化验证场景（jes-skills 有）
└─ tools/        可选：生成器/检查脚本
```

**硬约束只有三条**：模块根目录下**不再套一层**（不要 `核心文件/`、`src/` 这类包装层）；
`docs/` 三分区（AI 区 / 人工区 / 资料区）为模块标准配置；`sandbox/`、`tools/` 按需建。

| 2026-10-22 第三版（**现行**） | 明确「`mods/` 下每一层都是一个模块，命名 `作者-功能`」；取消「作者空间」概念；明确模块之间不嵌套、功能不嵌在别的模块里；`_shared/` 设启用条件 |
| 2026-10-22 补丁 | ①修正正文重复的 `## 七、` 编号（现状核对改为 `## 八、`）；②模块注册表回填 `jes-inventory` 状态（实验已收尾，保留为判据参照实现） |
