**红灯一条（审核方定位并修复，属「期望算错」不是实现错）**：

`test_repeated_inputs_with_same_seed_produce_identical_records_and_do_not_write_cfg` 末尾断言 `drops.size() == 2`，
实际 3。拆开算：容量 4、根开销 1 ——

- `a`（表现+逻辑各 1）→ 需要 3 ≤ 4，全收，**0 条丢弃**；
- `b`（同样两项）→ 需要 3+1+2=6 > 4，按优先级先丢表现层再丢逻辑层，**2 条丢弃**，根仍准入（占满 4）；
- `c`（空项）→ 4+1 > 4，**新根被拒，再留 1 条痕**。

合计 **3 条**。执笔方漏算了 `c` 的根拒绝 —— 而「拒绝新根也必须留痕」正是本卡的验收硬标准（不得静默丢弃），
且同一文件 `test_full_budget_rejects_new_root_...` 已断言 `after["drops"].size() == 1` 且等于 `rejected["rejected"]`，
**实现语义自洽，是测试期望写错**。

修法：改为 `3`，并补一条**组成断言** `drops.map(item_id) == ["b_fx","b_logic","c"]`，把「两次层丢弃 + 一次根拒绝」
显式钉住，避免以后有人再把根拒绝误当成「不算丢弃」。
