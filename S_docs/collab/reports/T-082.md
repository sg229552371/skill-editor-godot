## 核心口径（第 2 轮修订后）

1. **`ok` = 可解析 且（当前版本零诊断 或 版本不受支持）**，与 `CfgCodec.load_cfg` 的
   `ok = diagnostics.is_empty()` 同口径；已知版本带 block 诊断即 `ok:false`。
   但**失败仍带回 `cfg`/`data`**，编辑器照样能打开文件修复 —— 不制造「打不开的坏文件」。
2. **`data` 是 `cfg` 的增量别名**（U-37 第 3 条只增键）：既有消费者
   `addons/skill_editor/ui/skill_list_panel.gd:37-40` 读的是 `result.get("data")`，缺这个键则 UI 永远报「打开失败」。
3. **版本判定表驱动**：支持版本取自 `data/identity_meta.json` 的 `supported_schema_versions`；
   缺失或为空 → `ok:false` + `metadata` 诊断（不静默全标只读）。代码里没有 `"0.1"` 字面量分支。
4. **读失败与空文件区分**：走 `FileAccess.open` + `get_open_error()`，不再用 `get_file_as_string` 把读错误报成「空文件」。
