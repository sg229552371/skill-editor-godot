## 公开接口

- `var api: Variant`：可由宿主 `set("api", …)` 注入；面板不调用校验/保存 API。
- `configure(metadata: Dictionary, sorter: Variant) -> Dictionary`：注入严重度顺序与名称、双视图字段映射、默认卡展示来源元数据，以及已配置的排序器；缺项返回 `{ok:false,error:…}` 并在 `Status` 显示错误。
- `set_diagnostics(diagnostics: Variant, sources: Dictionary = {}, _overrides: Dictionary = {}) -> Dictionary`：接受原始诊断数组，委托注入的 `DiagnosticSorter.sort_diagnostics` 排序/去重；来源表为只读展示输入；覆盖表只作为只读入参，不保留、不修改；失败显式返回 `ok:false` 并清除旧条目。
- `get_view_entries(view: String) -> Array`：按策划/程序视图读取已渲染条目的脱离原诊断对象的副本。
- `get_entry_button(view: String, index: int) -> Button`：取指定可点击条目；`signal field_requested(path: String)`、`selected_path` 暴露定位路径。点相同条目不重复展开或重发信号；`location_emissions` 供无帧 headless 验证发出次数。

**真因（本卡唯一缺陷，属**素材数字类型**老坑的第三次变体）**：
```gdscript
var severity_index: int = order.find(item.severity)   # order 来自 diagnostic_meta.json → [0.0, 1.0, 2.0]
```
`Diagnostic.severity` 是 **int**，而素材 JSON 解析出来的 `severity_order` 恒为 **float**（坑 9），
`Array.find()` 在 int/float 混用时匹配失败 → `-1` → 面板判「诊断严重度未登记」→ 一条也不渲染 →
所有视图断言拿到空数组。**不是测试写错，是实现漏了口径。**

**审核方修复**：新增 `_severity_index(order, severity)` 按**数值**逐项比较（`int(value) == int(severity)`），
不再依赖 `Array.find` 的类型敏感相等；同时把「素材数字恒 float」的注释写进代码。修后 **8/8 PASS，99 asserts**。
