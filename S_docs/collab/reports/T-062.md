## 公开 API

- `configure(metadata: Dictionary) -> Dictionary`
  - 从注入的 `shapes` / `shape_renderers` / `shape_types` 读取形状名到绘制方式的映射。
  - 从 `damage_number_format`（兼容 `damage_format`、`damage_number.format`）读取伤害数字格式。
  - 缺少任一登记时显式返回 `ok:false`。
- `render_frame(items: Variant) -> Dictionary`
  - 已配置时校验完整帧，返回 `{ok, drawn, error}`。
  - 虽然冻结签名写作 `Array`，实现参数使用 `Variant`，以便非 Array 输入也能返回点名错误而不是在调用边界抛类型错误。
- `get_last_frame_items() -> Array`
  - 返回深拷贝快照；外部改写不会影响内部帧。
- `get_error() -> String`
  - 提供最近一次配置/帧错误文本。

## 帧模型最终形状

单项保留 `kind/pos/size/color/ttl` 及上游附加字段；`pos` 规范化为 `Vector2`，`size` 规范化为 `Vector2`，`color` 规范化为 `Color`。`shape` kind 使用帧项的 `shape`（兼容 `shape_name`），`damage_number` 使用上游 `text`，并按注入格式写入快照。`ttl <= 0` 不计入 `drawn`，也不进入 `_draw()` 的可见绘制。

与冻结契约的偏差：仅 `render_frame` 的参数类型从 `Array` 放宽为 `Variant`，原因是硬标准要求非法 `items` 返回结构化 `ok:false`；正常 Array 行为未改变。支持的注入元数据键增加了三个兼容别名，但没有新增业务策略。

## 审核方复核结论（WorkBuddy，2026-10-18 23:52 · 一轮 → **PASS（审核方修 2 处实现）**）

**首轮门禁**：5 用例 32 asserts，**4 条记 Unexpected Errors**，主错误
`Invalid call. Nonexistent 'String' constructor.`（`preview_viewport.gd:186`）。

**两处真因都是实现缺陷，不是测试写错**：
1. `_item_key()` 里用 `String(item.get("color", ""))` —— 但归一化后 `item["color"]` 已经是 **Color 对象**，
   Godot 4 **没有 `String(Color)` 构造器**（同理 `String(null)` 也没有）。整条 `render_frame` 抛错。
   修法：新增 `_key_text()`，`null → ""`、`Color → to_html()`、`Vector2 → "x,y"`、其余 `str()`。
2. 去重键格式串写了 **9 个 `%s` 占位符**，实参只有 **8 个** → `%` 运算 `validated_evaluate` 报错。
   修法：占位符改成 8 个（`"%s|%s,%s|%s,%s|%s|%s|%s"`）。
   顺带把 `_frame_fail(..., "未登记：" + String(shape_value))` 改成 `str(shape_value)`（`shape_value` 可能为 null，同一个坑）。

修后 **5/5 PASS，32 asserts**。

**验收复核**：三种图元（shape/trail/damage_number）都渲染且能读回；`drawn` 计数=3；
入参 items 前后 `JSON.stringify` 一致（**不写回**）；读回快照是深拷贝（改动返回值不影响面板）；
ttl 3→2→1→0 逐帧递减且 0 时 `drawn=0`；非法帧错误**点名** `item[0].kind` / `item[0].pos` / `items`；
