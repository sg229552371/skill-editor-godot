### 首跑红灯的真因（**不是你的设计缺陷，是夹具笔误**）

```text
ERROR: Parse JSON failed. Error at line 0: Unknown error getting token
   at: parse_string (core/io/json.cpp:629)
       [0] _json (res://tests/test_m6_end_to_end.gd:11)
       [1] _validation_context (res://tests/test_m6_end_to_end.gd:202)
```

`_validation_context()` 第 202 行写成 `_json("res://data/record_fields")` —— **漏了 `.json` 扩展名**，
`FileAccess.get_file_as_string()` 取空串 → `JSON.parse_string("")` 报错 →
GUT 的 **Unexpected Errors** 机制把**断言全部通过**的三条测试也判红（容易误判成「断言失败」，其实是「运行期有 error」）。

**处置**：补 `.json`，**未放松任何断言、未改生产行为**。复跑全绿。

> **固化**：看到 GUT 报 `Unexpected Errors` 时，先看是不是**夹具里的引擎 error**（文件读不到 / 解析失败），
> 不要急着去修断言 —— 这类红灯的断言数通常是 `53/56` 这种「没跑满」的形状。
