## 实现与调用契约

### 1. 每次施放一个协调器

`RuntimeDerive` 持有一个 `origin_cast_id` 的共享创建预算、FIFO、实例账本、消费事件和 debug 记录。各实例的代数、因果深度、来源链、访问集合及剩余局部预算存于私有账本；外部 CFG 与返回的 EffectBody 都不是该账本的权威。

入口（均为 runtime 内部接口，不改冻结 API）：

- `new(metadata_path, metadata_override, params_path, limits_path, limit_overrides)`：只读 `res://data/` JSON；static 缓存；缺失/解析失败/未注入 provisional 值写 `last_error`，阻止 configure。
- `configure(params, clock, bindings) -> bool`：消费已按模板展开的 params、T-040 逻辑时钟与显式派生预算绑定；深拷贝配置。`safety.max_chain_depth` 必须明确提供。
- `register_root(body, template_id, origin) -> bool`：根实例准入；计入 cast_budget，分配账本 seq；同一协调器不接受另一个 cast，不接受带父引用/非零代数或后代来源标记的根。**返回 false 的根不得被宿主加入调度。**
- `enqueue_event(event) -> bool`：接 T-044 的 `notify` 或 T-041 的 `step()` 结果。只认已登记实例的 hit/vanish；拒绝候选接触、结算记录、purge、非法原因、重复事件、终止后的重复事件，以及逆序/非当前 tick。
- `drain() -> {ok, events, children, records, error}`：在事件所在 tick 的阶段⑤调用，按入队顺序消费；`children` 为实际新建 EffectBody，供宿主接运动/结算与生命周期调度；`events` 是消费的原始事件副本，不是额外补发。
- `purge(body_id) -> bool`：调用生命周期 purge，取消该体尚未消费的派生工作，只记 debug，不补事件/实例。
- `snapshot_state()`：深拷贝账本；提供 `generation_remaining`、`depth_remaining`、共享 `cast_remaining` 及事件/记录，不能借返回值修改内部状态。

宿主须按实例账本 `seq` 稳定遍历，再依次调用 `enqueue_event`；协调器不按字符串 ID 重排 FIFO。不允许跨 tick 延迟 drain 后把瞬时子体建在过去：这种调度错误显式失败，保留队列供查错。

### 2. 派生与预算

- 事件枚举、7 种原因和受限原因来自 `params_meta.json`，没有原因码 if/elif 分派。
- hit 规则 reasons 必须为空；vanish 规则 reasons 必须非空。合法但不匹配的原因只消费事件，不自动创建。
- 受限原因必须在规则中写 **bool true**；`1`、字符串、容器、null 均不当授权。
- max_generation / cast_budget / max_chain_depth 的硬上限来自项目 JSON 加显式注入；配置越硬上限立即失败。provisional 的四个项必须分别覆盖，即使某个实例本身给了预算，也不豁免项目配置的未定值。
- 根第 0 代；子体 generation 与 origin.chain_depth 均 +1，相应 remaining -1。不读取子模板的预算初值回填后代。
- split/chain 的消费由显式 `bindings` 选择预算字段，不从模板名、trigger_id、子模板类型猜行为。一次分裂/继续操作扣一次局部额度；同批兄弟继承扣后的剩余值。**每创建一个实例另扣一次共享 cast_budget**，含根。
- 保留并推进 `origin_skill` / `origin_cast_id` / `proc_mask`、完整 `source_chain` 与 visited；重复 proc 标记阻断，连锁 visited 拒绝由显式绑定开启。候选接触家族账本仍归 T-046，不拿这里的成立 hit visited 冒充。
- 所有派生子体 `spawn_tick = event.tick + 1`，瞬时寿命仍为 0。实际测试夹具接 ShapeHit/Settle，覆盖先命中再 instant_end，不改 lifetime 凑窗口。
- 耗尽/截断有可查记录：`gen_limit` / `chain_depth_limit` / `budget_drop`（含 body、trigger、tick、requested 与预算 detail）；普通耗尽不抛运行时错误、不补偿 hit/vanish。大 count 先按余量限制循环，未创建部分合并记录。
- 没有新增随机派生概率。派生本身确定性；随机命中来自传入 SimClock 的逻辑流，经真实 RuntimeSettle 决定，表现 RNG 从不进入派生判定。

### 3. 显式预算绑定（不是 CFG 新字段）

```gdscript
{
    "root_template": {
        "trigger_point": {"budgets": ["chain_remaining"], "reject_visited": true}
    },
    "child_template": {}
}
```

- 通用派生显式填 `budgets: []`；分裂填 `["split_budget"]`；连锁填 `["chain_remaining"]` 并开启 visited 拒绝。模块只做通用字段消费，不按这些词写分派链。
- `trigger_id` 在当前 derivation Schema 非必填。缺省时运行期使用 `template_id:derivations[index]` 作为标识，不回填 CFG；绑定须使用同一键。此标识只对当前冻结的配置副本有效。
- 每个有派生规则的模板都必须有相应绑定；缺失直接失败，防止“没给分类就按无成本通用派生跑”。
