## 偏离记录、未决与风险（请勿把单文件绿当端到端 PASS）

1. **前置接线缺口仍在**：`shape_hit.gd:347-365` 在返回候选前已经扣候选额度、运行 resolver 并可能结算 hit；`settle.gd:284-297` 调用该 `step` 后才有记录/事件。仅修改本卡文件无法把家族拒绝挂在扣额之前，也无法在份处理之前按“是否成立 hit”阻断第二根的结算。新模块暴露 `admit`（候选额度之前）、`may_hit`（成功结算提交之前）、`record_hit`（成功提交之后）三个边界，**但这些不是现有 ShapeHit/Settle 已接入的钩子**。既有 ShapeHit 的 quota、Settle 的份记录/全闪避记录、目标生命与 `max_hits` 的真实端到端三断言待 WorkBuddy 扩权接线后验证，不能用本模块的账本断言冒充。
2. **运行期事实需宿主提供**：`sync_instances(snapshot, facts)` 必须传已解析 `facts[body_id]`：独立 `family_id`、`independent_root`、根实例实际 `shot_id`、根模板显式 `shotgun_allowed`（可缺省，由登记素材补 false）。不能从 `spawn_tick` 推断实际出手点，同 tick 两次出手也可能不同。新家族由新 ID 指定，来源链只来自 Derive 且不修改。
3. **分裂关系绑定未抽取**：Derive 的 `source_chain` 只证明血缘，不能证明行为是 split 而非 chain/explosion。必须由 WorkBuddy 提供经解析的 split-family 分组事实及爆炸新家族事实；缺事实显式失败，不把所有子代误作分裂。
4. **顺序调度边界**：调用方须把同 tick 候选交给 `admit_batch` 或先按 seq/target_id/part_index 排好队；单个 `admit` 不可能看到未来候选。成功 hit 的 `may_hit` 与 `record_hit` 须同一 FIFO 队列串行完成。被家族拒绝者不要交给 ShapeHit，也不要造 `evaded_all`；被防霰弹拒绝者的候选已成立，但成功伤害不得提交。现有 T-043/044 尚无两阶段、可回滚的候选/份提交 API，需审核方决定接线方案。
5. **编译风险**：两个脚本只做静态检查，未经引擎验证。没有修改 T-045/T-044/T-043，也没有创建模拟通过数。
