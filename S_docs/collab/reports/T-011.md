## 10.2 修复：函数头丢失导致整脚本编译失败

`--check-only` 原始输出：

```
SCRIPT ERROR: Parse Error: Function "_type_or_range_error()" not found in base self.
   at: GDScript::reload (res://skill_core/validate/rules/r_types.gd:160)
SCRIPT ERROR: Parse Error: Identifier "entry" not declared in the current scope.  (line 471)
SCRIPT ERROR: Parse Error: Identifier "value" not declared in the current scope.  (line 472)
SCRIPT ERROR: Parse Error: Cannot return a value of type "String" as "Array[String]". (line 473)
...
```

**根因**：`_field_aliases()` 之后是一段**没有函数头的函数体**（`entry` / `value` 两个参数没有声明、返回 `String` 却被前面 `Array[String]` 的上下文吞掉），
即 `_type_or_range_error(value, entry) -> String` 的**函数签名行在编辑中丢失**，V-020 的类型/范围判定逻辑变成游离代码。
这是本项目「三个坑」之外的**第四类坑**：*GDScript 不会因为函数体游离而只报一处，它会把后续所有未声明标识符与返回类型冲突一并抛出，第一条报错（line 160 `not found in base self`）才是真正的定位点*。

**修复**：补回签名行 `func _type_or_range_error(value: Variant, entry: Dictionary) -> String:`，函数体一字未动。

> 已并入 `CLAUDE.md` 坑位清单（第 5 条）：写完函数体先确认签名行存在；`--check-only` 报「Function X not found in base self」时，直接跳到该处看是不是函数头丢了。
