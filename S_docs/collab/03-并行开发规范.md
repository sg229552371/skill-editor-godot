# 并行开发规范（2026-10-18 23:45 起生效）

> 起因：用户指出「开发速度太慢」。审核方做了数据化归因，并把并发度从 **2 → 5**，
> 改法是**文件所有权隔离**（不靠 worktree，见 §3 的理由）。

## 一、速度归因（实测数据，不是感觉）

| 环节 | 实测 | 占比判断 |
|---|---|---|
| 单个 CLI 派单（写代码+写测试+写回执） | **3–8 分钟** | 主要耗时 |
| 单文件门禁（check-only + GUT） | 2.4 秒 | 可忽略 |
| 全量回归（29 文件串行） | ~70 秒 | 可忽略 |
| **返工轮次** | 平均 **1.8 轮/卡**（T-015 2 轮、T-016 **3 轮**、T-023 2 轮、T-024 1 轮+审核方修） | **真正的放大器** |
| 审核方写复核结论 | 2–4 分钟/卡 | 次要 |

**结论：慢的不是引擎、不是测试，是「并发度 2」+「返工轮次」。**
返工的真因集中在四类，已逐条进派单前置条件：

1. 执笔方**没跑基线**就断言（坑 13：区间断言恒真）。
2. 执笔方**只走注入不接真实素材**（坑 14：掩盖素材口径 bug）。
3. 字段名/素材形状靠猜（V-075 的 `carrier` vs `carrier_mode`）→ 派单里改为**点名文件与行号**。
4. 冷启动重读真源：每个 `claude -p` 都是新会话，项目上下文要重新加载 ~1 分钟。

## 二、本轮调整（已执行）

1. **并发 2 → 5**：5 条泳道同时跑，物理隔离靠**文件所有权**（§3）。
2. **派单模板加三条前置**：①先跑基线断面拿到干净基线；②照抄同类卡测试里的辅助函数；
   ③涉及字段名必须回 `data/*.json` 或规则实现里核对，不许按中文名推英文名。
3. **U-16 / U-19 定稿**（`data/project_config.json`）：`tick_rate=60`、`max_generation=4`、
   `cast_budget=64`、`max_chain_depth=8`、`defaults.cast_budget=64`。
   素材里的 `_provisional` 标记**保持不动**（示例值仍是示例值），运行期一律注入项目配置 —— 这样既解锁
   M5/M6 的 10 张卡，又不破坏 T-048/T-045 已有的「provisional 未注入即失败」测试。
4. **门禁批处理**：同一波次的多张卡，编译检查与 GUT 一次性串行扫完再统一出结论，不再一卡一停。

## 三、为什么不用 git worktree
本仓库 5 条泳道写的文件**两两不相交**（见 §4），共享文件（`plugin.gd`、`data/*.json`、`CLAUDE.md`）
**只有审核方改**。worktree 的收益是"防同文件双写"，代价是每个工作树要重新 `--import`
（Godot 类缓存 + `.godot/` 重建，分钟级，且引擎有单实例锁）—— 在当前场景**净亏**。
真正要防的是「CLI 跑 git 回滚误伤他人文件」，这条已在派单里硬禁（`git checkout/clean/stash/revert/restore` 全禁）。

## 五、集成节奏
每波次结束：审核方统一跑门禁 → 全量回归 → 判 PASS → 一次提交（合并成一个 commit，便于回溯）。
**判 PASS 的前提仍是「有原始输出 + 断言未被弱化」**，并发度提高**不降低验收标准**。
