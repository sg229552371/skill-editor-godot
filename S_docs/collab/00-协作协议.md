## 一、角色边界（不可越界）

| 角色 | 承担者 | 做什么 | 明确不做 |
|---|---|---|---|
| 用户 | 用户 | 拍板方向性决策；验收最终交付 | 不介入实现细节 |
| **执笔方** | WorkBuddy **主会话** | 按任务卡写代码、写 GUT 测试、跑门禁、产出回执；维护 WBS 与决策台账；维护素材与协作文档 | 不自行判自己的回执 PASS；不擅自改规格真源；不擅自扩任务范围 |
| **审核方** | **独立审核子 Agent**（每次新起、无上下文） | 按第五节判据复核 diff 与门禁原始输出，判 PASS/REJECT，给出 `文件:行` 级阻断项 | **不改任何文件**；不看实现思路与自评理由；不替用户做方向性决策 |

**越界判定**：
1. 主会话**对自己的回执判 PASS** → 该回执无效，须重派独立审核子 Agent。
2. 主会话未经用户拍板修改 `S_docs/技能系统书-v1.md`（规格真源）→ 越界，回执作废。
3. 审核子 Agent **写入任何文件**（含批注以外的改动）→ 该次审核作废，重派。
4. 协作文档（`00~03`）由主会话维护，但每次改动必须在回执「偏离记录」登记文件与行号，并经审核子 Agent 复核。

规格有疑问走「条款质疑」流程（见第五节）。

## 三、目录与文件所有权（并行前提）

并行开发的**唯一冲突源是同文件写入**。所有权按目录切分，越权写入一律 REJECT。

```
res://
├── skill_core/                    【线 A/B/C 共用，所有权按子目录细分】
│   ├── api/                       ← T-000 冻结，之后任何人只可读不可改（改需申请）
│   ├── schema/                    ← 线 A（T-001~006）
│   ├── validate/                  ← 线 A（T-010~016）
│   ├── resolve/                   ← 线 B（T-030~035）
│   ├── modify/                    ← 线 B（T-030~035）
│   └── runtime/                   ← 线 C（T-040~048）
├── addons/skill_editor/           ← 线 D 独占（T-020~027）
│   ├── plugin.cfg / plugin.gd
│   └── ui/
├── tests/                         ← 谁写的模块谁写对应测试，文件名前缀区分
│   ├── test_schema_*.gd           ← 线 A
│   ├── test_validate_*.gd         ← 线 A
│   ├── test_resolve_*.gd          ← 线 B
│   └── test_runtime_*.gd          ← 线 C
└── data/
    ├── bricks/brick_catalog.json  ← 线 A 独占（T-003）
    └── skills/*.yaml              ← 示例与夹具，各线自建子目录
S_docs/collab/reports/T-xxx.md     ← 主会话写，审核子 Agent 批注（判定结论段）
```

**铁律**：
- `skill_core/` 下**禁止** `import` 任何 `EditorPlugin` / `EditorInterface` / `@tool` 编辑器 API。core 必须在 `--headless` 下能被 GUT 直接测。这是「后续游戏内玩家编辑器复用同一 core」的前提，也是可测性前提。
- UI 层（`addons/skill_editor/`）只能调用 `skill_core/api/` 暴露的函数，不得直接读 YAML 或直接摸 `skill_core` 内部类。
- 新增目录必须先在回执中报备，由主会话更新本协议并提交审核子 Agent 复核。

## 四、任务流转（拆卡 → 实现 → 回执 → 独立审核 → 回收）

```
主会话拆任务卡（01-WBS）
      │
      ▼
主会话实现 + 写 GUT 测试 + 跑门禁（全部绿）+ 自检
      │
      ▼
写回执 S_docs/collab/reports/T-xxx.md（模板见下）
      │
      ▼
派「独立审核子 Agent」（每次新起，无上下文）
  输入只给：任务卡原文 / git diff + 新增文件全文 / 门禁原始输出 / 第五节判据表
      │
      ├──PASS──▶ 回执追加判定段，WBS 打勾，解锁下游任务
      │
      └──REJECT──▶ 阻断项（文件:行）回主会话修正 → 重跑门禁 → 重派新审核子 Agent
```

**关键约束**：主会话**永不**给自己的回执写 PASS。审核结论只能由独立子 Agent 产出；
主会话在审核前只能写「待审」状态。重提必须**新起**子 Agent，不得复用上一轮审核上下文。

### 回执模板（主会话必须逐项填写，缺项直接 REJECT）

```markdown
# T-xxx 回执
- 任务 ID / 名称：
- 改动文件清单（绝对路径，新增/修改分开列）：
- 依赖任务与接口版本：
- GUT 结果：`gut` 命令行原文输出，含 通过数/失败数/跳过数
- 验收逐条自证（任务卡「验收标准」每一条 → 对应测试函数名 → 结果）：
- 真源条款对照（读了真源哪几行 / 用了哪个素材）：
- 偏离记录（任何与任务卡不一致处，含理由）：
- 未决与风险：
- 自检：是否越权写文件？是否硬编码策略？core 是否可 headless 测？
```

### 审核判据（独立审核子 Agent 专用；主会话提交前自检同样适用）

| 判据 | PASS 条件 | 常见 REJECT 理由 |
|---|---|---|
| 范围 | 只动了任务卡列出的文件 | 顺手改了别的模块、顺手「优化」了规格 |
| 测试 | 有测试且 `gut` 全绿，输出原文贴出 | 只说「已测试」无输出；测试恒真（无断言/断言空集合） |
| 验收 | 任务卡每条验收都有对应测试函数 | 验收例子对空集合执行全部成立判断（真源 20.1 明令禁止） |
| 数据驱动 | 策略进配置/素材，代码通用 | 把 28 个积木 ID 写死在 `if/elif` 里；把枚举值硬编码成魔法字符串 |
| 契约 | 不改真源、不改冻结接口 | 私自加字段、私自放宽严重度 |
| 可测 | core 无编辑器依赖 | core 里 `@tool` 或 `EditorInterface` |

## 五、冲突处理与升级路径

1. **条款看不懂** → 先查 `assets/_raw_*.md` 对应章节原文，再查真源行号。
2. **条款互相冲突** → **不要自行选一个实现**。登记到回执「未决与风险」，标两处原文行号，继续按较严口径实现并标 TODO，由独立审核子 Agent 裁决。
3. **发现真源缺口** → 写进回执，不写进真源文件。
4. **需要新接口** → 提「接口变更申请」：现状 / 需求 / 影响面 / 建议落点，审核子 Agent 裁决后再动 `api/`；涉及冻结契约的按第 5 条上升用户。
5. **确需用户拍板** → 只有满足下列之一才升级：改变交付范围、改变架构分层、改变已冻结数据契约、影响玩家可感知玩法、改变本协议的角色与流程。其余一律在 WorkBuddy 内解决。

## 六、硬门禁（每次提交前）

| 门禁 | 要求 |
|---|---|
| 测试 | `gut` 全绿；core 层新增逻辑必须有对应测试文件 |
| 校验 | 编辑器任何保存路径都必须过 `validate/`，禁止「先存了再说」 |
| 落盘 | 一律 UTF-8 YAML；禁止重复键、自定义执行标签、隐式布尔、非有限数字；时间只存整数 tick |
| 命名 | 文件 snake_case，类名 PascalCase，`brick_id`/`skill_id` 必须过 `snake_id` 正则 |
| 提交 | 一次提交一个任务卡，commit message 开头带 `T-xxx` |
| 回写 | 运行结果、实例编号、快照**禁止**写回技能 CFG（真源 3.5） |

## 八、审核子 Agent 输入契约（v1.1 新增）

审核的独立性靠**输入隔离**保证，不靠模型差异。每次审核**新起一个子 Agent**，只给以下四类输入：

| # | 输入 | 形态 |
|---|---|---|
| 1 | 任务卡原文 | `01-WBS` 中对应 T-xxx 全文（含验收标准与禁止事项） |
| 2 | 代码变更 | `git diff` 全量 + 新增文件全文（未提交时用 `git diff HEAD`） |
| 3 | 门禁原始输出 | `gut` 逐文件输出、`--check-only` 退出码、全量回归汇总行，**原样粘贴** |
| 4 | 审核判据 | 本协议第四节判据表 + 第六节硬门禁 |

**明确不喂**：实现思路、自评理由、本轮对话历史、上一轮审核结论。
**输出固定三段**：

```
一、判据逐条结论（范围/测试/验收/数据驱动/契约/可测，各 PASS|FAIL + 依据）
二、阻断项（若有）：文件:行 + 判据 + 最小修正建议
三、结论：PASS | REJECT
```

**权限**：只读。审核子 Agent 不得 Edit/Write 任何文件，也不得跑会写盘的引擎命令；
需要它验证的问题，由主会话把命令输出补进输入后重派。
