# 第 15 章　报错文案

〔2026-10-18 第1轮〕文案必须回答“哪里错、为什么不能接受、下一步改哪里”，不只写失败。规则 ID 服务追踪，字段路径服务定位，文案服务理解；三者不能互相代替。

## 15.1 展示与占位规则

同一规则可以复用一个模板，但必须传入不同的实际字段。策划视图默认显示中文字段名、当前值、修改建议，展开后显示完整 Schema 路径和依据；程序视图同时显示规则 ID、文案 ID、实际类型和相关引用。两个视图使用同一份诊断，不能一个说警告、另一个说错误。

占位内容作为纯文本插入，不执行表达式，不解释为 Markdown 链接或脚本。引用 ID、路径、输入值长度超出界面可展示范围时，界面截断但详情可复制完整值。缺失值显示“未填写”，空数组显示“空列表”，两者不能都渲染为空白。中文字段名未登记时回退到完整路径，不能显示未定义。

## 15.3 多错误、建议与无障碍定位

多个字段不合法时按阻止保存、警告、提示排序，同严重度按章节表单顺序和数组下标排序，最后以规则 ID 破同分。不得按异步返回顺序乱跳。点击一条诊断应展开折叠区、定位字段、保持旁边的契约说明可见；若字段位于积木默认值，先显示“错误来自默认卡”而不是自动把默认值复制到覆盖区。

自动修复只允许无语义变化的操作，例如去除标签集合重复项；修复前显示差异并允许取消。版本迁移、载体替换、修改派生入口、增加权限、改变预算不能作为“一键修复全部”默默执行。错误提示中的示例值只供解释，不能自动填成最终数值。对可修复结构错误与运行时契约失败，按钮文案应分别为“定位填写项”和“查看探针差异”。

同一问题经规范化影响多个输出字段时，先定位作者实际输入，再展示关联结果，不能把展开出的十个后果当成十个独立错误。相反，不同修饰器分别越权时必须分别报告，不能因为文案相同合并丢掉来源。复制诊断时带上版本、规则和路径，避免评审收到一张截图后无法知道对应哪份定义。
