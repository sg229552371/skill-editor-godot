## 一、本卡任务

### 能力 1：`create_sim(cfg: Dictionary, seed: int = 0) -> Dictionary`（真实入口）

内部构造 `options` 后委托 `PreviewRunner.start(cfg, options)`。**options 构造口径**：

| 键 | 口径 |
|---|---|
| `seed` | 直接取本函数入参。**真源 16.1 的确定性种子，禁止内部造默认值** |
| `roots` | **从 CFG 的 `bricks` 推导**：每个「根积木」一条 root，`template_id` / `shot_id` 取自积木登记，`instance_id` 由 API 内部分配。**判定哪些积木是根必须按 `data/brick_catalog.json` 的载体分类表驱动**，禁止 `if-elif` 硬编码积木 ID |
| `handlers` | **坑 21**：按 `data/params_meta.json` 的 `enums.part_type` 建**全量 handler 表**；用不到的类型绑**显式返回 false 的 `_unsupported_part`**，绝不绑静默成功的空 handler |
| `project_config` | **不传**，让 PreviewRunner 走既有 `_read_json(CONFIG_PATH)` 路径，保持既有行为 |

返回：`ok=true` 时返回包含 `ok` / `diagnostics`（空数组）/ `sim`（句柄）/ `fingerprint`；
`ok=false` 时逐层透传 PreviewRunner 的 `_failure` 内容（`path` / `error` / `diagnostics`），
**不得把失败吞成空包**。

### 能力 2：`step_sim(sim: Variant, ticks: int = 1) -> Dictionary`（真实入口）

从句柄取 runner 调 `advance_ticks(ticks)`。
返回包含 `ok` / `diagnostics` / `snapshot`（`snapshot_state()` 结果）。
`ticks` 非正整数 / 句柄无效 → `ok=false` + diagnostics，**不得抛异常**。

### 能力 3：预览双入口同夹具差分（U-28 步骤 6 的 S6a/S6b 证据）

`tests/test_skill_api_sim.gd` 里必须给出**同一张真实 CFG、同一夹具**的两条运行：

- **正式入口**：`CfgCodec.save_cfg(user://.../t077_case.skillcfg, cfg)` 落盘 →
  `CfgCodec.load_cfg(同路径)` 读回 → `api.create_sim(loaded_cfg, seed)` → `RunDiff.capture(...)`
- **预览入口**：直接 `PreviewRunner.new().start(同 cfg, 同 options)` → `RunDiff.capture(...)`
- `RunDiff.compare(trace_a, trace_b)` → **首差异为空**（有差异必须报出首个差异路径，不得静默）

⚠ **落盘路径一律用 `user://t077/`**（headless 可写、不污染 `res://`、不进 git）。
**禁止**在 `res://` 下新建 CFG 文件（会连带产生 `.import` / `.uid` 未跟踪文件）。
