## 验收硬标准

1. **只消费逻辑事件**：`hit` 与 `hit_settled` 都能触发对应 cues；传入 `anim_finished` / `animation_callback` /
   `on_anim_end` 之类**动画回调名** → `ok=false` 且错误点名该名（**这就是 V-072 的运行期守卫**）。
   - 用例要**成对**：合法事件成功 + 非法回调名失败，不能只测一边。
2. **表现回调不得产生逻辑写入**：`on_event()` 前后对入参 payload 与 bindings 深拷贝 + `JSON.stringify` 比对一致；
   并且断言 `on_event` 的返回结构里**没有**任何可回写逻辑的字段（例如不允许返回 `damage` / `hit_delta` /
   `next_tick` / `end_reason` 这类逻辑字段 —— 用**禁用键清单**断言，清单本身从注入的
   `presentation_meta.forbidden_logic_keys` 读，**不要让核心写死**；若素材没有这一段，就用本卡注入的
   `configure(bindings, presentation_meta)` 里传，并在回执里写明「素材缺该段，暂由注入」）。
3. **V-074 对齐完整性**：`anim` 段启用（非空）时，每个 `alignments[i]` 必须同时有 `shot_tick`（int）与 `frame`（int）；
   缺任一 → `configure()` 显式失败并点名 `presentation.anim.alignments[i].shot_tick` / `.frame`。
   - 用例：全齐 → ok；缺 `shot_tick` → 失败点名；缺 `frame` → 失败点名；**空 anim 段 → 允许**（空段＝未绑定，不继承隐藏默认）。
   - `shot_tick` 必须是整数 tick（**不是秒**）：传 `0.5` 秒这类非整数 → 失败；传 `int` 或 JSON 的 `30.0` → 接受并 `int()`（坑 9）。
4. **七段都参与**：七个段名各有一个用例（或一个用例遍历七段），证明段名与 cues 映射来自注入素材，
   **换 bindings 后 cues 随之变化**（证明没写死）。
5. **未 configure 调用 `on_event` → 显式失败**；`configure` 失败后 `alignments()` 返回空数组且 `get_error()` 非空。
