## 背景与契约（T-050 正在并行落地，签名已冻结，按此写，不要等）


测试里用**桩**验证调用序列，用**真 runner** 验证一次端到端能起能停。**不要**在 launcher 里 `preload` 真 runner 当唯一路径。

## 验收硬标准（每条都要有用例，且断言是「逐项比对」不是「非空即可」）

1. **初态/种子/输入必须显式固定**：`launch()` 传给 runner 的 `options` 里，
   `seed`、`inputs`、`initial_state`（或项目里既有等价键名 —— **先去 `preview_runner.gd:61 start()` 读它到底认哪些键**，
   不许按中文名猜英文名）必须来自**调用方显式传入**。
   - 用例：不传 seed → **显式失败**（`ok=false` + 错误点名字段），**绝不允许**用时间戳/随机兜底；
   - 用例：两次同参 `launch()` → 传给 runner 的 options 逐字段相等（深比较），且**不含**任何时间/随机来源。
2. **版本切换必须显式化**（真源 3.6）：切换版本 = `stop()` → 重新 `start()`，
   **不允许**在旧 run 上原地改 CFG 续跑。用例：`switch_version()` 的调用序列必须是 `stop` 在前、`start` 在后，
   且新 `start` 收到的是**新版本 CFG**（断言传参内容，不是只看返回值 ok）。
3. **不得用热更新绕开 live 权限**：本卡不实现任何热更新通道；
   用例：`launch()` 传入 `options` 含 `hot_reload=true` 之类未登记键时 → **显式失败并点名该键**
   （未登记 ≠ 忽略；这是全项目口径）。
4. **不写回 CFG**：`launch()` 前后对入参 cfg 做深拷贝 + `JSON.stringify` 比对一致。
5. **未注入 runner 时显式失败**（不是 `null` 崩，也不是静默 ok）。
6. **runner 返回失败要原样透出**：桩返回 `{ok:false, path:"cfg", error:"..."}` 时，
   launcher 的 `ok=false`、`error` 包含原 `path` 与 `error`，且**不伪造成功**。
