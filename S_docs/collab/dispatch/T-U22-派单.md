## API 要求（形状可按现有代码风格调整，但语义必须是这些）
```gdscript
# configure(catalog_entry: Dictionary, policy: Variant = null) -> Dictionary  # {ok, error}
# query(path: String) -> Dictionary
#   {ok: bool, error: String, path: String,
#    locked: bool, lock_reason: String,      # 锁定 = 作者不可改
#    open: bool,                              # 开放 = 该路径当前对作者可编辑
#    source: String,                          # "author_params" / "default_cfg" / "relic_params" / "locked" / "modifier" / "unknown"
#    writable: bool}                          # 结论位 = open and not locked
# query_all() -> Array                        # 逐路径全量，顺序 = 目录声明顺序
```
- **必须显式失败**：未 `configure()` → `query()` 返回 `ok:false`；未知路径 → `ok:false` + `source:"unknown"`（不要静默返回 writable=true）。
- **只读**：不缓存可变引用，不修改传入的 catalog/policy，不写回任何 CFG。
- **不做校验**：本卡不产生诊断、不判严重度，只回答「这四个事实是什么」。

## 验收硬标准
1. 锁定路径：`locked:true`、`writable:false`、`lock_reason` 非空且来自素材（**不许写死字符串常量**，理由文本从 `locked_params` 或 `item_permission_policy.json` 取）。
2. 作者可写路径：`locked:false`、`open:true`、`writable:true`、`source:"author_params"`。
3. 未开放（不在 `author_params` 也不在 `locked_params`）：`open:false`、`writable:false`，但 `locked:false`（**两者不同义，必须能区分**）。
4. 默认卡来源：出现在 `default_cfg` 的路径 → `source:"default_cfg"`，且 `writable` 按 3 的口径。
5. 素材侧路径带 `[i]`（如 `arrays[0].path`）与作者侧路径（如 `bricks[2].author_params.x`）**两套判据都过**：各至少 2 条用例，且互不误判（坑 10）。
6. 未 configure / 未知路径 → 显式失败，且 `query_all()` 在未 configure 时返回空数组 + 记录错误。
7. 只读证据：传入 catalog 深拷贝前后 `JSON.stringify` 一致；`query_all()` 返回表被外部修改后不影响后续查询（返回副本）。
8. **表驱动**：不出现任何具体积木 ID / 字段名 / 理由文案的硬编码分支；换一份 catalog 与 policy，结论随之变化（至少一条用例证明）。
