## 四、验收硬标准

1. **少一个顶层键 → 报错**；多一个顶层键 → 报错（七键逐个正反向：删一个 / 加一个第八键）。
2. **`bricks[i]` 少任一字段 → 定位到实际槽位**：报错 path 必须是 `bricks[2].author_params` 这种**精确路径**，
   不许报成「参数对象」/「bricks 里有问题」。（V-013 展开为 12 个槽位，逐槽位正反例。）
3. **七表现段**：缺任一段 → 报到 `presentation.fx` 这类实际槽位；出现第八段 → 报错。
4. **类型**：七种类型各有正反例；`tick_fields` 里的整数类型字段必须是整数（**素材数值按坑 9/坑 14：素材侧 `is int or is float`，
   只有作者填进 CFG 的值才严格 `is int`**）。
5. **枚举**：`enums` 表内的枚举字段，值不在表内 → 报错；**枚举选项必须来自素材，不许写死在代码里**。
6. **必填**：按 `objects[].required` 与载体/能力条件判定；
   **素材未登记「必填」的字段，一律显式「未登记」，不许推断**（与 T-023 的九列口径一致，见其回执）。
7. **附加键**：`additional_properties: false` 的段出现未登记键 → 报错到该键路径；为 true 的段允许。
8. **表驱动**：结构定义全部来自素材/已冻结常数，测试是通用循环 + 正反例表；
   **禁止为某个具体字段写 if 分支**，禁止硬编码字段名、枚举值、严重度。
9. **不修改入参**：校验不得写回传入的 CFG（`duplicate(true)` 前后 `assert_eq`）。
10. **素材缺失 → 显式失败**（D-21），不许静默当缺省。

## 五、坑位清单（前 15 张卡踩出来的，逐条避开）

1. `:=` 遇 Variant 推断失败 → **整脚本编译失败**；用 `var x: Variant = …` 或显式类型。
2. `dict.get(k, {})` 可变默认值掩缺键 → 默认 `null` + 命中后回写父节点（D-20）。
3. 禁在 `_init()` 里解析 md/yaml/RegEx；运行期只读 `res://data/`（D-22）。
4. 函数头丢失时，`Function X() not found in base self` **第一条**才是真定位点。
5. **Variant 跨类型比较抛运行时错误** → GUT 记 Unexpected Errors；先转 `String` 再比。
6. 点语法给 Dictionary 写新键生成 **StringName**（`has("x")` 取不到）→ 新键一律 `dict["k"] = v`。
7. `Diagnostic` 只有 `SEV_BLOCK/WARN/HINT`，**没有** `SEV_INFO`。
8. 给**显式类型变量**赋 null 抛运行时错误 → 容器取值先声明 `Variant` 再 `is` 判定。
9. **JSON 解析出来的数字恒 float**：素材数值用 `is int or is float`；作者 CFG 值才严格 `is int`。
10. 素材路径含 `[i]` 与作者 CFG 键（禁 `[`/`]`）是**两套判据**。
11. 素材 `_` 前缀键是注释，遍历/建索引必须跳过。
12. **测试里别调 GUT 不存在的方法**（`fail()` 不是 API）→ 解析期炸、`Nothing was run`、**0 用例假绿**；
    要制造必然失败用 `assert_true(false, "…")`。
13. **区间/集合型断言会恒真**：先跑基线，断言「相对基线新增」（`_new_in_range`）。写每条断言前问：基线下它是不是本来就满足？
14. 坑 9 的隐藏变体：**素材侧严格 `is int` 会把 `1.0` 判非法**（T-016 在 `r_modifier._limit()` 上真炸过）。
15. **新增脚本的 `class_name` 不能当类型名用**（不在全局类缓存里）→ 一律 `const X = preload("res://…x.gd")` 再做类型标注。
