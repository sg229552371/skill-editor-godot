# T-072 派单 · ED-17-13 霰弹全闪避重复结算修复

## 问题定位（已由 T-052 探针实测）

`tests/test_ed17_repro.gd` 的 ED-17-13 探针断言：同一 `shot_id` 的两根独立子弹、对同一目标**全部闪避**时，
当前产出 `evaded_all = 2`；按真源应为 **1**。

根因在 `skill_core/runtime/family_ledger.gd`：

- `may_hit()`（约 :224-248）的去重条件挂在 `member["independent"] and not member["allowed"]` 下的 `_shot_hits` 检查；
- `record_hit()`（约 :250-258）**只在成功命中时**写 `_shot_hits`；
- 于是「首根被闪避 → 没写去重键 → 第二根照样结算 → 第二条 evaded_all」。

`record_hit()` 上方的注释写着 "The shotgun gate checks *successful hits*, not contacts."——
这句话解释的是**为什么被拒绝的候选不消耗 max_hits**，不能拿来当「全闪避也不去重」的依据。两件事要分开。

## 判定口径（本卡按此实现，回执要自证）

同一 `(origin_cast_id, family, shot_id, target_id)` 是**一次攻击对该目标的一次判定**：

- 已判定过 → 后续根**不再产出任何结算记录**（既不 hit 也不 evaded_all），也不消耗 `max_hits`；
- 判定结果取**第一根**（先到先得），后到的不改写；
- **不同 `shot_id` 互不影响**（ED-17-06：两根不同 shot 打 HP10 目标仍应 hit=2 / killed=1）；
- **被容量/预算拒绝**的候选仍然**不**登记（`may_hit` 返回 denial 的情况不改现有语义）。
