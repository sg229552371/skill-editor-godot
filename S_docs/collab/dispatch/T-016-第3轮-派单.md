## 一、审核方已直接修的 core bug（**不要动 `r_modifier.gd`**）

第一轮 84 条里**每一条**的「相邻合法边界」都报 `出现 BLOCK`，实际是同 6 条基线诊断：

```
V-053 sev=0 path=bricks[0].default_cfg.params.max_generation  exp=…project_limits.defaults.max_generation 不可用…实际 1.0
V-053 sev=0 path=bricks[0].default_cfg.params.max_generation  exp=不超过项目硬上限的非负整数 actual=未填写
（bricks[1]、bricks[2] 各两条，共 6 条）
```

**真因**：`r_modifier.gd` 的 `_limit()` 对**素材侧**数值用了严格 `value is int`。
而 `res://data/project_limits.json` 解析出来的 `defaults.max_generation` 是 **float 1.0**（**坑 9**：JSON 数字恒 float），
于是「项目默认不可用」→ 每个积木各 2 条 → 基线永远不干净。
T-012 自己的测试用注入整数，所以 41/41 全绿没暴露 —— **一旦走真实素材就炸**（和坑 11 同家族）。

**修法（已落）**：`_limit()` 改为「数值且为整数值」判定（`is int or is float` → `float()` → 有限且 `floor(n)==n` → 返回 `int(n)`），
**注入值与素材值一视同仁**（两者都可能来自 JSON）。修完基线诊断 **0 条**，T-012 复跑仍 **41/41（774 asserts）**。

→ 你**不要**再改 `skill_core/validate/rules/r_modifier.gd`。
