## 必须实现的行为（三条硬要求来自真源）
1. **基线被更新时不覆盖（V-081）**：保存时若发现磁盘上的基线版本已变化，**拒绝静默覆盖**，返回显式状态
   `{ok:false, reason:"baseline_advanced", ...}`，并给出「另存为 / 以基线为准重载」两条后续动作标识
   （只返回动作枚举，不实现 UI 弹窗）。
2. **未知版本只读不降级（V-083）**：读到 `schema_version` 高于当前支持 → 进入 `read_only` 状态，
   **不迁移、不降级、不写回**；后续任何 `save()` 必须显式失败。
3. **未改内容重复保存不产生假修订**：内容指纹相同 → 不递增 `revision`，不触发写盘；
   返回 `{changed:false, revision:<原值>}`。

## API 形状（可按现有风格微调，语义不可改）
```gdscript
# configure(validator: Variant, codec: Variant, limits: Dictionary) -> Dictionary
# load(text: String, context: Dictionary) -> Dictionary   # {ok, cfg, revision, read_only, reason, diagnostics}
# save(cfg: Dictionary, context: Dictionary) -> Dictionary # {ok, changed, revision, reason, fingerprint}
# fingerprint(cfg: Dictionary) -> String
```
- `revision` 单调递增，**由本卡维护**，初值 1；不依赖外部时间戳。
- `context` 契约沿用 T-015 裁定：save 入口需 `schema_version_state` 等既有事实，缺则显式失败（不要自己造默认值）。

## 验收硬标准（每条至少一个用例，且断言是"相对基线"的增量，防恒真，坑 13）
1. 正常保存 → `ok:true, changed:true, revision` 递增 1。
2. 同内容再存 → `changed:false`，`revision` 不变，且**未调用写盘**（用注入的假写盘计数证明，禁止靠"没报错"推断）。
3. 基线前进后保存 → `ok:false, reason:"baseline_advanced"`，**磁盘内容未被覆盖**（用假写盘记录证明）。
4. `schema_version` 未知（更高）→ `read_only:true`；随后 `save()` 返回 `ok:false`，且 `cfg` 未被改动（深拷贝比对）。
5. 指纹：同内容不同键顺序 → 相同指纹；改一个叶子 → 指纹变化（证明是规范化指纹，不是 `JSON.stringify` 原样、不是 `hash()` 随机）。
6. 入参 CFG 不被修改：保存前后 `JSON.stringify` 逐字节一致。
7. `configure()` 缺失依赖 → 显式失败；未 configure 调 `save/load` → 显式失败（不是静默 ok）。
8. 表驱动：不出现具体 V 规则号/字段名硬编码分支。
