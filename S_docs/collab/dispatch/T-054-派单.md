## 契约（冻结）
```gdscript
# configure(project_config: Dictionary) -> Dictionary            # {ok, error}；缺 tick_rate → ok:false（D-21）
# compute(cfg: Dictionary, seed: Variant, extra: Dictionary = {}) -> Dictionary
#     # {ok, error, fingerprint: String}  —— 规范化指纹，键顺序无关
# certify(fingerprint: String) -> void            # 记录「上次通过验收」的指纹
# state_for(cfg: Dictionary, seed: Variant) -> Dictionary
#     # {ok, error, fingerprint: String, certified_fingerprint: String,
#     #  match: bool,             # 当前 CFG 是否等于通过验收的那份
#     #  save_verdict: String,     # "allow" | "allow_with_notice"
#     #  certify_verdict: String,  # "block" | "allow"
#     #  notice: String}           # save 侧提示文案（来自注入或素材，不写死中文）
```

## 验收硬标准
1. **指纹规范化**：同内容不同键顺序 → 相同指纹；改一个叶子 → 变化；改 `seed` → 变化；改 `tick_rate` → 变化
   （证明 tick_rate 进了指纹，且来自注入：给 60 与 30 应得不同指纹）。
2. **D-30 两入口分流**：`match=false` 时 `save_verdict="allow_with_notice"`、`certify_verdict="block"`；
   `match=true` 时两者分别是 `"allow"` / `"allow"`（**不许把 certify 也放行**）。
3. **不使用覆盖表**：代码里不出现"把指纹写回 CFG"或"覆盖旧指纹"的路径；`compute()` 不改入参（深拷贝+`JSON.stringify` 比对）。
4. **缺 tick_rate 显式失败**；未 configure 调 `compute/state_for` → 显式失败。
5. **notice 文案来自注入**（`configure` 可传 notice 或从素材读），不写死中文字符串；换文案后输出随之变化。
6. 表驱动：无具体技能 ID / 字段名硬编码分支。
