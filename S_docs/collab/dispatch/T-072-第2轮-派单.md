## 根因（已定位，不用再查）

`_shot_group_key(member, target)` 与既有 `_shot_key(member, target)` **逐字段同构**，都是
`[origin_cast_id, shot, target]`。而你把这个组键的**写入放在了 `may_hit()` 里**。

于是这条链就断了：

1. `may_hit(second)`（预检，模拟「第一根全闪避所以放行第二根」）→ **写入** `_shot_groups[group] = second`；
2. `record_hit(first)` 内部先调 `may_hit(first)` → 看到 `_shot_groups[group] == second != first` → **判 shotgun 拒绝**；
3. 第一根没结算 → `shot_hits` 为 0、`reason` 为空 → 三个断言全红。

`may_hit()` 是**预检查询**，既有实现里它一行状态都不写（`_shot_hits` 只在 `record_hit()` 写）。
你在预检里写判定表，等于「问一句就占坑」。这是本轮的病根。

## 必须这样改

1. **删掉 `_shot_groups` 整个成员**，以及它在 `may_hit`、`purge`、`snapshot_state` 里的全部引用。
   它与 `_shot_key` 同构，纯冗余，且是本次回归的唯一来源。
2. **`may_hit()` 恢复为无副作用**：只读 `_shot_hits` 与 `_shot_judgments`，不写任何表。
3. **`_shot_judgments` 只在判定真的完成后写**：新增公开方法
   ```gdscript
   func record_judgment(candidate: Dictionary) -> bool
   ```
   语义：一次接触对某目标的所有份量已结算完毕（**命中或全闪避都算**），登记该
   `(origin_cast_id, family, shot, target)` 已判定；重复登记同一 body 幂等返回 true，
   不同 body 试图重复登记同一 key → 返回 false。
   **必须复用 `_candidate_error()` 做前置校验**，与 `record_hit` 一致。
4. **`may_hit()` 的拦截条件**：`_shot_hits` 命中过 **或** `_shot_judgments` 已判定，且持有者不是当前 body
   → `{ok:true, allowed:false, reason:"shotgun"}`。两条判定要**分别**判断再合并，不许合成一个键。
5. `snapshot_state()` 增加 `shot_judgments` 键（保留 `shot_hits`、`members`、`families`、`last_tick` 原样）。
