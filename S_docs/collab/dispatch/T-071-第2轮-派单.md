你问：「是否批准上述 runner 最小补充范围？」——**批准**。以下是精确边界，超出即越权。

## 已批准（全部允许）

`res://skill_core/runtime/preview_runner.gd` 允许做这 **6 类**改动：

1. **成员**：新增 `_hosts`（注册表实例）与适配器状态容器。命名以 `_host_` 前缀，不得与既有成员重名。
2. **section 检查改派注册表**：`start()` 里那五 section 的循环，改为查 `_hosts.has_adapter(section)`；
   有适配器则 `_hosts.validate(section, template[section], ctx)`，失败原样返回该 `path`/`error`；
   无适配器保留拒绝，文案必须含 `Host adapter` 与 section 名。
3. **抽取根启动**：把 `start()` 里创建根的那段逻辑抽成私有方法（建议 `_launch_root(root_input: Dictionary) -> Dictionary`），
   让 `start()` 与 emissions 消费共用同一条路径。**抽取必须行为等价**：预算校验、派生登记、家族登记的调用次序与参数不许变。
4. **消费 emissions**：新增私有方法（建议 `_consume_emissions(emissions: Dictionary) -> Dictionary`），
   把 `spawn` 交给 `_launch_root()`，`events`/`records` 追加到既有流。**只认四键** `spawn/attach/events/records`，
   出现第五个键必须失败并点名（这是契约的一部分，要有测试）。
5. **tick 0 消费**：`start()` 成功末尾消费一次 `advance(state, 0, ctx)` 的 emissions，使 `shot_ticks=[0]` 能即时出手。
6. **每 tick 消费**：`advance_ticks()` 内每 tick 调一次 `_hosts.advance()` 并消费 emissions；
   顺序必须是「先推进时钟/既有逻辑 → 再消费 emissions」，不得插到既有 tick 逻辑中间。
