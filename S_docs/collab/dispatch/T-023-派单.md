## 一、任务

为技能编辑器做**参数表单**：按真源第 5 章的**九列参数登记**动态生成控件，让策划能填一张技能卡的 `params`（+ 覆盖积木默认值）。

**真源第 5 章的九列**（`S_docs/技能系统书-v1.md` 第 1905 行起，先读）：
`字段名 | 类型 | 默认值 | 取值范围 | 单位 | 必填 | 分级 | 所属积木 | Schema 路径`

硬规则（真源，逐条遵守）：
- 类型只用冻结的七种：`int / float / bool / enum / string / ref / array`；组织容器不另登记为 object 参数。
- **分级**（新手/进阶/专家）是**展示层级，不是三套规则**：隐藏高级项**不能删除它的值**；
  展开专家项**不能获得修改锁死参数的权限**。
- 无默认值须显式登记为「无默认」，**不能把空值、零和未填写混为一谈**。
- 同名字段因所在集合不同而不同义，**以完整路径为主键**。
- 未知路径不降级为任意 JSON 输入，未知引用不当作无操作。
- 表单的「必填」按载体与能力条件判断（不能要求纯表现技能填飞行速度）。

**WBS 验收三条**：① 锁定项不可填；② 秒/tick 双显且落盘只存 tick；③ 未开放参数不出现在表单。

## 三、九列的素材现状（先读，别臆造）

`res://data/params_meta.json` 现有顶层键：`leaves`(path/type/unit/enum)、`arrays`、`objects`、`tick_fields`、
`enums`、`rule_field_aliases`、`restricted_reasons`、`_source`。

**已登记**：字段名（path 末级）、类型（type）、单位（unit）、Schema 路径（path）、枚举取值（enums）。
**未登记**：默认值、取值范围、必填、分级、所属积木。

处理口径（照此执行，不许猜数字）：
- **默认值 / 所属积木** → 从 `res://data/brick_catalog.json` 各卡的 `default_cfg` / `author_params` /
  `locked_params` / `relic_params` 取（真源第 4 章：开放哪些行由 `author_params` 决定）。
- **取值范围 / 必填 / 分级** → 素材未登记的列，表单**显式渲染为「未登记」**并禁用相应推断行为
  （不要自己造范围、不要把「未登记」当不必填），同时在回执里列出「缺哪些列、需要我补抽什么」。
- 素材缺键/缺列 → **显式失败或显式「未登记」标记**，不许静默当缺省（**D-21 素材缺失显式失败**）。

## 四、验收硬标准（测试必须逐条覆盖）

1. **开放/未开放**：`author_params` 开放的行渲染出控件；未开放的行**不出现**在表单里（按完整路径匹配，
   同名不同路径互不串）。relic 场景取 `relic_params` ∩ 暴露字段（`ExposedFields`）的交集。
2. **锁定项不可填**：`locked_params` 命中的路径 → 控件不可编辑，并显示锁定原因文本
   （`locked_params` 的值就是原因）；用户尝试改也不产生变更。
3. **秒/tick 双显，落盘只存整数 tick**：
   - 单位属于 `tick_fields` 的字段，界面同时显示秒与 tick；
   - 提交秒 → 落盘值必须是**整数 tick**（`SkillUnits.seconds_to_ticks`，向上取整）；
   - 提交 tick → 秒显示按同频率回算；
   - **项目 tick 频率必须由 `SkillUnits.configure(project_meta, …)` 注入**（未决 U-19，禁硬编码 60）：
     测试用**两个不同频率**跑同一输入，断言结果不同 —— 证明不是写死的。
4. **变更表而非直接落盘**：表单只产出「路径 → 值 + 来源标记（default/params/brick_override/relic）」的变更表；
   **不直接写 CFG、不做校验**（校验归 `validator.gd`，保存归后续 T-025）。
5. **分级三档**：隐藏「进阶/专家」组时，这些项的**值仍然保留**（不能丢）；
   展开专家组时，**锁定项依然不可编辑**。
6. **七种类型各有控件**：`int / float / bool / enum / string` 至少各一条用例（`ref` / `array` 若素材暂无登记，
   渲染为「未登记类型」并显式标记，不许当成 string 输入框糊过去）。
   enum 的选项**来自素材 `enums`**，不写死在代码里。
7. **空值/零/未填写三者区分**：`null`（显式未填写）、`0`、`[]`（空列表）在表单与变更表里是三种不同状态，
   不互相塌缩。
8. **素材缺列不崩**：删掉素材某列的场景（测试里构造一份缺列 metadata 注入）→ 表单显式标「未登记」且不抛运行时错误。

## 六、坑位清单（前 13 张卡踩出来的，逐条避开）

1. `:=` 遇 Variant 推断失败 → **整脚本编译失败**，用 `var x: Variant = …` 或显式类型。
2. `dict.get(k, {})` 可变默认值掩缺键 → 默认 `null` + 命中后回写父节点（**D-20**）。
3. 禁在 `_init()` 里解析 md/yaml/RegEx。
4. 函数头丢失时，`Function X() not found in base self` **第一条**才是真定位点。
5. **Variant 跨类型比较抛运行时错误**（int vs String）→ GUT 记 Unexpected Errors；比较前先转 `String`。
6. 点语法给 Dictionary 写新键生成 **StringName** 键（`has("x")` 取不到）→ 新键一律 `dict["k"] = v`。
7. `Diagnostic` 只有 `SEV_BLOCK/WARN/HINT`，**没有** `SEV_INFO`。
8. 给**显式类型变量**赋 null 抛运行时错误 → 容器取值先声明 `Variant` 再 `is` 判定。
9. **JSON 解析出来的数字恒为 float**：素材数值禁用 `is int` 单判（`is int or is float`）；
   作者填进表单的值才严格 `is int`（tick 落盘必须是 int，显式转）。
10. 素材路径含 `[i]` 与作者 CFG 键（禁 `[`/`]`）是**两套判据**（`LockGuard` 已拆分，别混用）。
11. 素材里 `_` 前缀键（`_note`、`_source`）是**注释**，遍历/建索引必须跳过。
12. **测试里别调 GUT 不存在的方法**（`fail()` 不是 `GutTest` API）→ 解析期炸、整脚本不加载、
    GUT 显示 `Nothing was run`、**0 用例假绿**。要制造必然失败用 `assert_true(false, "…")`。
13. UI 测试跑在 **headless**：不要依赖 `EditorInterface`、真实文件系统对话框、或需要主循环迭代多帧的逻辑；
    需要信号/就绪时用 `await` 也要保证 headless 下能返回。
