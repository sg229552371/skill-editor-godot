## 必须实现的行为
1. **与正式读取同一份 CFG**：runner 不持有独立 schema 分支，吃 `cfg_codec` 解析出来的同一结构；
   传入非法 CFG → 显式失败（不静默空跑一场"什么都没有"的预览）。
2. **固定当前配置快照**：`start()` 时对 CFG 做深拷贝快照并算指纹；运行期外部改 CFG **不影响本场预览**。
3. **实例编号不由编辑器预填**：实体 id 由 runner 内部单调分配（同 T-047 的 seq 口径），
   外部传入的 `instance_id` 只作为**建议值**且必须被校验/覆盖，不允许出现"编辑器填什么就是什么"。
4. **跑起来是真的**：至少支持「根技能 → 弹道飞行 → 命中 → 结算 → 派生分裂 → 预算裁剪」这条链路，
   事件只有 `hit` / `vanish`（D-08），逻辑/表现 RNG 分离（D-09）。

## 验收硬标准（重点：别用桩糊过去）
1. 一条完整链路用例：发射 → 推进 N tick → 至少 1 次 `hit`、至少 1 个派生体产生，
   断言**实际实体数与事件序列**（不是"没报错"）。
2. 快照隔离：`start()` 后修改原 CFG 的伤害数值 → 本次预览结算值仍按快照（改前值）。
3. 实例编号：注入一个与内部计数冲突的 `instance_id` → 不产生重复 id（断言 id 集合无重复）。
4. 预算：构造超出 `cast_budget` 的分裂 → 触发裁剪且**留痕**（记录条数与 T-048 口径一致）。
5. **tick 频率注入**：同一 CFG 分别用 `tick_rate=60` 与 `tick_rate=30` 跑同样的 1.0 秒（各自换算 tick 数）
   → 结算时刻/事件 tick **不同**；且**移除 tick_rate → 显式失败**（证明没写死 60）。
6. 非法 CFG（缺关键段）→ `ok:false` + 点名缺失路径；不进入运行态。
7. 确定性：同输入同种子跑两次，事件序列逐项相同。
8. 表驱动：无具体技能 ID / 字段名硬编码分支。
