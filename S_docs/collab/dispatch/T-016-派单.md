## 四、验收硬标准

1. **覆盖率**：84 条 V 每一条都有一条反例断言「诊断中出现该 `rule_id`」，
   一条边界断言「同一 `rule_id` 不出现」。最小 168 条断言；允许一条 V 有多组反例。
   最终必须打印/统计「已覆盖 V 条数 = 84 / 84」，缺一条就判失败（不要写死 84 这个数在断言里，用素材 CSV 行数或区间表算出）。
2. **严重度不写死**：反例命中后，期望严重度从 **`res://data/validation_rules.csv`** 读（**D-27：严重度唯一真源是 CSV**），
   与诊断的 `severity` 比对。CSV 缺该行 → **显式失败**（不要静默跳过）。
3. **通用类型规则必须覆盖这些变体**（真源 20.3）：零值、边界值、缺省（键不存在）、`null`、
   「字符串数字」（如 `"3"` 当 int 用）、非有限数（`inf`/`nan`）、超范围。
   反例表里按「变体」维度组织，而不是一条 V 一个魔法数字。
4. **关联规则先造「引用都存在但语义仍非法」**（真源 20.3 末段）：
   例如引用目标存在但类型/权限/作用域不匹配、来源合法但目标不接受该修饰器 —— 这类至少覆盖关联类规则。
5. **相邻合法边界要真合法**：边界 CFG 不得触发**任何** BLOCK 级诊断（可以允许 WARN/HINT），
   否则说明你的「合法基线 CFG」本身不合法，先修基线。
6. **表驱动**：反例/边界的 CFG patch、路径、期望严重度来源全在数据表里；
   测试代码只做「读表 → 构造 → 调 validator → 比 rule_id/严重度」的通用循环。
   **禁止在测试里为某条 V 写专属 if 分支**。
7. **不修改入参**：validator 不得写回入参 CFG/context（已有 T-015 覆盖，本卡若发现写回照实报告）。
8. **运行期禁止解析 md/yaml**：只从 `res://data/` 读 JSON/CSV（**D-22**）。

## 五、坑位清单（前 12 张卡踩出来的，逐条避开）

1. `:=` 遇 Variant 推断失败 → **整脚本编译失败**，用 `var x: Variant = …` 或显式类型。
2. `dict.get(k, {})` 可变默认值掩缺键 → 默认 `null` + 命中后回写父节点（**D-20**）。
3. 禁在 `_init()` 里解析 md/yaml/RegEx。
4. 函数头丢失时，`Function X() not found in base self` **第一条**才是真定位点。
5. **Variant 跨类型比较抛运行时错误**（int vs String）→ GUT 记 Unexpected Errors；比较前先转 `String`。
6. 点语法给 Dictionary 写新键生成 **StringName** 键（`has("x")` 取不到）→ 新键一律 `dict["k"] = v`。
7. `Diagnostic` 只有 `SEV_BLOCK/WARN/HINT`，**没有** `SEV_INFO`。
8. 给**显式类型变量**赋 null 抛运行时错误 → 容器取值先声明 `Variant` 再 `is` 判定。
9. **JSON 解析出来的数字恒为 float**：素材数值禁用 `is int` 单判（`is int or is float`）；作者填进 CFG 的值才严格 `is int`。
10. 素材路径含 `[i]`（如 `derivations[i].on`）与作者 CFG 键（禁 `[`/`]`）是**两套判据**。
11. 素材里 `_` 前缀键（`_note`、`_source`）是**注释**，遍历/建索引必须跳过。
12. **测试里别调 GUT 不存在的方法**（`fail()` 不是 `GutTest` API）→ 解析期炸、整脚本不加载、
    GUT 显示 `Nothing was run`、**0 用例假绿**。要制造必然失败用 `assert_true(false, "…")`。
