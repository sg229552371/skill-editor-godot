【真源口径（真源 16.1，逐字）】
「所有数字必须有限，逻辑时间以整数 tick 保存。编辑器可以提供秒数输入，但换算后只提交 tick 值，

【审核方裁定（直接采用，不要再自行推断）】

1. **项目频率不是常量，必须注入**。真源**没有冻结**「多少 tick 等于一秒」（全篇只说「项目频率」），
   因此**禁止硬编码 60 或任何默认值**。`configure(project_meta)` / `set_rate(...)` 由外部注入 `tick_rate`
   （每秒 tick 数）；**缺失 → 显式失败**（D-21），不得静默套用 60。
   （该值的最终取值已登记为未决项 U-19，与 U-16 一并由用户拍板；本卡只要求「必须注入」。）
2. **换算规则：向上取整**（`ceil`）。1.001 秒 @60 → **61** tick。恰好整除不 +1。
3. **只做换算，不做语义范围判定**。「非负」「正数」这些范围由校验器管（V-0xx / `params_meta`），
   units 不夹取、不修正、不把负数改成 0。但**非有限数与负数在换算前显式失败**：
   - `NaN` / `Inf` / `-Inf` → 显式失败；
   - 负数秒 → 显式失败（没有物理意义，不得夹到 0）；
   - 字符串秒（如 `"1.5"`）→ 显式失败（作者可乱填的字段必须先转类型，不得隐式解析）；
   - `null` 与「缺省」区分：缺省不参与换算（不是错误），显式 `null` → 显式失败。
4. **已是整数 tick 的输入原样通过**，不得二次换算（幂等）。非整数 tick 输入 → 显式失败
   （逻辑时间只存整数 tick，不接受 1.5 tick）。
5. **tick 字段集合来自素材**：从 `res://data/params_meta.json` 的 `tick_fields`（15 个）读取，
   **禁止硬编码字段名**。新增 tick 字段应只需改素材，不改代码（用例要证明）。
6. **界面双显数据由本卡产出**：返回结构里要带 `rate`（采用的项目频率）、`seconds`（输入）、
   `ticks`（向上取整结果）、`field`；界面据此展示，但**落盘只提交 tick**。
7. **反换算（tick → 秒）只允许用于展示**，且必须标记用途（返回值里带 `display_only: true` 之类），
   **不得写回 CFG**。
8. 素材缺失/解析失败 → 显式失败，不得退化成「零字段即通过」。
9. core 内无任何编辑器 API（禁 `@tool` / `EditorPlugin` / `EditorInterface`），保持 headless 可测。

【验收硬标准】
· 向上取整专项：1.001 秒 @60 → 61 tick；2.0 秒 @60 → 120 tick（整除不 +1）；0 秒 → 0 tick
· **项目频率注入不同值结果随之改变**：注入 30 / 60 / 120 三档，同一秒数得到不同 tick（三条用例，不是写死 60）
· 频率缺失 / 0 / 负数 / 非数字 / 字符串 → **逐项显式失败**（不得夹取、不得猜）
· 非 tick 字段（如 `damage`、`max_range`）**不得被换算**：传入也显式失败或拒绝（裁定：**显式失败**，不要静默放过）
· tick 字段集合来自素材：注入扩展后的素材（多一个 tick 字段）→ 新字段也参与换算，**代码不改**
· 幂等：已经是整数 tick 的输入原样返回；1.5 tick → 显式失败
· 非有限数 / 负数秒 / 字符串秒 / 显式 null → 显式失败；缺省（键不存在）不算错误
· 反换算只用于展示且有标记；**不写回 CFG**（有断言：入参 CFG 前后深度相等）
· 不修改入参 CFG
