## 必须实现的连线（每条都要有测试）

1. **启动即就绪**：`editor_panel` 实例化后，10 个模块**全部**创建并进入场景树，且各自的 `configure()` 返回 `ok=true`。
   少一个、或任一 `configure` 失败 → 面板必须在可见状态区显示**点名错误**，不许静默跳过。
2. **打开技能 → 全链路刷新**：`skill_list_panel.skill_opened(cfg)` 后：
   `param_form.set_context(...)`、`modifier_panel.configure(...)`、`presentation_panel.configure(...)`、
   `diagnostic_panel.set_diagnostics(...)` 全部被调用，且**用的是同一份 cfg**（不许各模块各读一遍盘）。
3. **选砖 → 装配 → 重渲染**：`brick_selected(brick_id)` 后，装配结果必须来自 `skill_core/api/skill_api.gd`，
   **不许在 UI 里拼 CFG**；装配失败 → 错误进 diagnostic_panel，不吞掉。
4. **改参数 → 校验 → 诊断面板**：`param_form.values_changed` 后触发校验，`set_diagnostics` 收到的诊断
   与直接调 validator 对同一 CFG 的结果**逐项相等**（字段、规则号、严重度、路径）。不许只断言「非空」。
5. **保存往返**：`save_flow.save(cfg)` 后把文本 `load()` 回来，字段集合与值**深比较相等**（不丢未知字段，见 D-23）。
6. **试放链路**：`launch → advance_ticks → snapshot_state → preview_panel.ingest → preview_viewport.render_frame`，
   四步任一失败都不许继续下一步，错误进可见状态区。
7. **幂等**：同一面板连续 `skill_opened` 同一 cfg 两次，**信号连接数不增长**（用 `get_signal_connection_list` 实测数量），
   三栏/表单内容不重复堆叠。
8. **失败可见**：任一模块 `configure`/`ingest`/`save` 返回 `ok=false`，组合根必须把 `error` 原文放进状态标签，
   **不得**只 `push_warning`。

## 硬性约束

- **不许把策略写进 UI**：列名、字段名、枚举、预算数值一律从 `res://data/*.json` 或模块返回里取；UI 里出现类型字符串分支即违规。
- **不许跨层**：`editor_panel.gd` 可以 `preload` core 的公开入口（`skill_api`、`validator`、`cfg_codec`），
  **不许**访问 core 私有成员、不许 `FileAccess` 直读 `res://data/` 绕过模块。
- **不许在 `_ready()` 里解析 md/yaml**（坑 3）；素材只读 JSON（D-22）。
- `plugin.gd` 只负责 `_enter_tree` / `_exit_tree` 挂载卸载；**所有连线在 `editor_panel.gd`**。
- 所有 Variant 取值先声明 `Variant` 再 `is` 判定；新字典键用 `dict["k"]`；禁 `:=`。
- `const` 常量名**不得与原生类同名**（坑 17：Panel/Label/Timer/Color/Node…；现象 `tests=0`）。
- 测试里 preload 的类一律 `const XxxPanel = preload(...)` 这类**带前缀**的名字，禁 `const Panel`、`const Label`。
