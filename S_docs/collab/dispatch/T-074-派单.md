## 已知的三类变化（供你判断，不要照抄）

1. **07（timing）/ 18（attached）/ 22（summon）**：这三个 section 仍**没有**适配器，
   但错误文案从 `Host adapter not implemented in T-050` 改成了
   `Host adapter not implemented: <section>`。你的断言若匹配旧文案就会红。
   → 这属于 B 类：断言「`error` 同时包含 `Host adapter` 与 `timing`/`attached`/`summon`」，`path` 指向该 section。

2. **09 / 10 / 12 / 19（cast）**：cast **已被接受**，`start()` 不再拒绝。
   但适配器只实现了**前摇 / 出手 tick / 冷却**三件事：
   - 09 的「位移施放请求 / 窗口恢复 / 过期丢弃」→ 适配器不管位移请求 → 大概率 B 类；
   - 10 的「控制暂停 / 恢复前摇 / 打断取消」→ runner **无打断入口**
     （`test_runner_host_integration` 里已诚实标 pending）→ B 类；
   - 12 的「动作 / 实际出手数 X 账本」→ `shot_count` 有了，但 X 账本没有 → 需你逐项拆开判断，
     **可能一半 A 一半 B**：若拆开，就写成两个断言组，别硬凑一条；
   - 19 的「原子换装 / 同 tick 出手 / 公共冷却」→ 冷却有了，换装没有 → 同样可能拆开。
   → 这四条**必须逐字段读真源与适配器实现**再判，不许按本派单的猜测直接改。

3. **`_entities.is_empty()` 已放宽**：带 cast 的模板在前摇期零实体不再判失败。
   所以 09/10 那类用例现在**能进入前摇态**，原来"start 直接失败"的断言形式必然失效。
