# T-080 派单 · ED-17-19 原子换装：**让装配被真实消费**，并把 19 从缺口探针转为正向验收

> 本卡沿用 T-076 第 6 轮「只做一件事」的成功范式：**一件事 = 装配真正影响新出手创建的实例**。
> 分 **A / B 两段**，A 完成即有价值；B 做不完就 A 交付 + B blocked，不要为了凑全而把红灯留在树上。

## 一、本卡任务

### A 段（硬底线）：让装配影响**新创建的实例**，且**不回溯改动旧实例**

1. **新出手读到完整新装配**：换装边界应用后，紧接着创建的实例必须带**当前**装配值。
   - 正向断言要求：分别换装 **A 槽 / B 槽 / 整批两槽**，三次都要观测到**新实例**读到**对应的新值**；
   - **不许只断言 "发射成功了"** —— 必须读取实例上的实际参数值并断言等于新装配值。
2. **旧实例保留**（三条分开观测，不许合并成一句「没崩」）：
   - **参数**：换装前已存在实例的装配参数**数值不变**；
   - **行为**：它在后续 tick 继续按旧参数推进（例如仍发射旧速率/旧模板，取可观测的一条）；
   - **快照**：`snapshot_state()` 里该实例的装配相关字段前后一致。
3. **装配走向的建议方案**（默认采纳；你有更好方案可在回执里单独提出由审核方裁，
   但**不要擅自改方案又不说明**）：
   - host 在 `apply_equipment_boundary` 后，把装配快照作为**发射上下文的一部分**随 emissions 交出；
   - runner 在 `_launch_root` 创建实例时把它**固化进实例初态**（深拷贝）；
   - 此后再次换装**只影响之后创建的实例** —— 「固化」天然满足第 2 条「旧实例保留」。
   - **❌ 禁止**把装配做成「全局当前值」，实例运行中去实时查 —— 那会让旧实例随换装漂移，直接违犯第 2 条。

### B 段（能力被 A 段验证后）：把 ED-17-19 从「缺口探针」转为「正向验收」

既有裁定（见 `02-决策台账.md`，ED-17 系列通用规则）：
**缺口探针绿 ≠ 验收通过；能力补齐后探针应当变红，此时改为正向验收断言，
绝不反向改 core 恢复旧行为。**

1. `data/fixtures/ed17.json` 的 `ED-17-19` 转正。**先读全文件再改**，注意本素材的既有约定：

   - `status` 的合法取值只有 **`"ok"` 与 `"blocked"` 两种**（当前 24 条里 7 ok / 17 blocked），
     **没有 `"pass"`** —— 改成 **`"ok"`**，不要自造取值；
   - `verification` 目前 24 条**全是 `"not_run"`**（统一占位），**保持不变**；
2. `tests/test_ed17_repro.gd` 的 `test_ed17_19_partial_skill_cooldown_but_atomic_equipment_absent`（`:593` 起）
   **只改这一个函数**：
   - 函数体第 2 行 `assert_eq(c["status"], "blocked", ...)` → 改为断言 **`"ok"`**（与本素材 status 取值一致）；
   - 函数尾部的**词汇探测循环**`for name in candidates: assert_false(methods.has(name))`
     保留不动（能力是以英文方法名落地的，中文词汇本来就不该出现，这条仍成立）；
   - **PUBLIC_API 六入口断言集体不动**（本卡不新增 runner 公开方法，见 §二）；
   - 函数名保留（历史引用），在上方注释写明「原为缺口探针，T-080 转正」。
3. `tests/test_ed17_capability.gd`（现有 5/5·230，**只追加**）：A 段的正向验收 ≥ **3 条** ——
   新装配被新实例读取（A/B/整批）+ 旧实例三观测。

## 三、验收标准

1. **硬**：换装后**新实例**读到**新**装配值（A/B/整批三种情形，读实际参数值断言）。
2. **硬**：换装前已存活实例的**参数 / 行为 / 快照**三条各自观测，换装前后不变。
3. **硬**：**坑 13 非空对照** —— 必须证明「装配确实被读取」：
   构造一个「不换装」的对照组，其新实例装配值**与换装组不同**；
   若两组结果相同，则该验收**未证明**（空集合恒真），须回执写明并改夹具。
4. **硬**：`ED-17-19` 的 fixture status 与 `test_ed17_repro` 探针**同步转正**（B 段）。
5. **硬**：全量门禁不劣于 **54 文件 / 675 用例 / 674 通过 / 14219 断言 / Failing 0 / Risky 1 / bad=0**。
6. **降级**：A 段成立、B 段做不到 → 交付 A 段 + B 段如实 blocked，**门禁必须绿**。
   **唯一不可接受的是把红灯留在树上。**

## 四、硬条款（违反即 REJECT）

1. **禁止运行引擎**（Godot / GUT / `--check-only` / `--import` / `--script` / 进程查询）。
   回执写「**自测声明：未运行引擎，已静态复核**」。门禁由审核方串行跑。
2. **禁止任何 git 写操作**；**禁止会写 git 元数据的隔离型工具**（坑 18）。
3. **GDScript 坑**：一律显式类型（`var x := dict.get(...)` 对 Variant 推断失败会让整脚本编译失败）
   · 不用可变容器作 `get(k, ...)` 默认值（会掩盖「键不存在」，写入全部丢失）
   · Nil→Array 防护（坑 8：`var v: Variant = d.get(k, null); var a: Array = v if v is Array else []`）
   · JSON 数字一律 float · 运行期禁止解析 schema 全文（D-21）
   · **函数体内 `const X = preload(...)` 在嵌套 lambda 里解析不到，一律提升到脚本级**。
4. **坑 22**：写完自查缩进，**别在已有行前插多余 tab**（曾出现凭空多 61 个 tab）。
5. **不得放松断言、不得 pending / skip 掩盖红灯**；回执如实列出所有触碰文件（含只读）。
6. 写「已通过」但没跑过 = 伪造门禁，直接 REJECT。
7. **进度保底（分阶段落盘）**：**每完成一步就落盘并追加进回执**。
   宁可回执写「A 段完成，B 段 blocked」，**不可零产出**。
   特别提醒：本卡由 T-076 拆出，而 T-076 **第 2/4 轮两次零产出静默中断**，
   根因判定为**单卡范围过大** —— 本卡已按此经验拆细，**请不要再自行扩大范围**。
8. **除了 §二 列明的四个改动文件，不得修改任何其他既有 .gd / .json**（含测试）。
