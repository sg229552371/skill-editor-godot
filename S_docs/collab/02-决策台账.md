## 二、WorkBuddy 拍板〔推荐默认〕

### D-01 分层：core 与 UI 壳分离

- **决策**：`res://skill_core/` 为纯数据层，**禁止引用任何编辑器 API**；`res://addons/skill_editor/` 为 UI 壳，只调 `skill_core/api/`。
- **理由**：①Godot 编辑器 API 在 `--headless` 下不可测，core 不依赖它才能保证 GUT 100% 覆盖；②用户已确认后续要做游戏内玩家编辑器，同一 core 换 UI 壳即可复用，成本最低。
- **扩展口**：未来第二个宿主（游戏内 UI）直接引用 `skill_core`，无需改动。

### D-02 落盘格式：UTF-8 YAML，自研 `YamlLite` 子集编解码器

- **决策**：`skill_core/schema/yaml_lite.gd` 自研解析器 + 序列化器。
- **依据**：已核实 **Godot 4 无内置 YAML 支持**（仅有 JSON / ConfigFile-INI）。第三方有二：`YAML.gd`（纯 GDScript，MIT，Godot 4.0）与 `godot-yaml` GDExtension（RapidYAML，声明支持 4.3+）。
- **选自研的理由**：①真源 16.1 已明令禁止重复键、自定义执行标签、不能展开为普通值的引用结构、隐式布尔 —— 所需仅是 map/seq/scalar/多行块子集，实现量小；②GDExtension 二进制在 **4.7.1** 上无官方预编译保证，兼容风险不可控；③第三方解析器普遍宽松静默，反而要再加一层拦截；④自研可把「拒收」做成一等公民，直接对应 V-019 / E-0011。
- **退路（扩口，不预先实现）**：若自研超预期，切 `YAML.gd`（纯 GDScript，零编译）；`CfgCodec` 保持后端可切换，JSON 后端作为内部交换/调试快照格式。
- **边界**：YamlLite **只支持**：嵌套 map、seq、标量、引号字符串、`|` / `>` 块、注释、空行。**明确拒绝**：锚点 `&`、别名 `*`、自定义标签 `!!`、多文档 `---`、键顺序语义。拒绝即报错，不静默降级。

### D-03 测试：GUT + 固定 headless 门禁命令

- **决策**：测试目录 `res://tests/`，按线分前缀（`test_schema_*` / `test_validate_*` / `test_resolve_*` / `test_runtime_*`）。
- **门禁命令（已实测跑通）**：

  # 步骤 1：预热导入（保证 class_name 注册）
  "$GODOT" --headless --path . --import --quit

### D-16 测试门禁：逐文件 `-gtest=` 串行，禁用 `-gdir`（2026-10-18 实测）

- **事实**：`-gdir=res://tests -ginclude_subdirs` 模式实测**挂起 5 分钟无输出**直到超时被杀；而 `-gtest=res://tests/<文件>.gd` 单文件模式**0.4 秒**出结果。
- **决策**：全量门禁 = 对每个 `res://tests/test_*.gd` **串行循环**跑 `-gtest=`，绝不用 `-gdir`。
  ```bash
  GODOT="C:/Users/Administrator/AppData/Roaming/Ryko.GodotHub/godot-versions/4.7.1-stable/Godot_v4.7.1-stable_win64.exe"
  for f in $(ls tests/test_*.gd); do
    timeout 120 env GODOT_DISABLE_LEAK_CHECKS=1 "$GODOT" --headless --display-driver headless \
      --audio-driver Dummy --path . -s res://addons/gut/gut_cmdln.gd \
      -gtest="res://$f" -gexit
  done
  ```

### D-19 编译自检：`--check-only` 是 CLI 唯一可跑的 godot 命令（2026-10-18）

```bash
GODOT="C:/Users/Administrator/AppData/Roaming/Ryko.GodotHub/godot-versions/4.7.1-stable/Godot_v4.7.1-stable_win64.exe"
timeout 60 "$GODOT" --headless --check-only --script res://<文件>.gd
```

- 坏文件 → 退出码 **1** + `Parse Error: ... (文件:行号)`；好文件 → 退出码 **0** + 无输出。
- 关键性质：**不导入项目、不写 `.godot/`、不跑测试** → 无并发崩溃风险，可放心交给 CLI 自查。
- CLI 写完**每个** `.gd` 都要跑，退出码必须 0 才准进回执。
- CLI **仍被禁止**：`--import`、`--path`、`-s gut_cmdln.gd` 及一切 GUT 命令（归 WorkBuddy 独占）。
- **WorkBuddy 侧流程**：每轮收口前跑一次**全量 check**（对所有 `skill_core/`、`addons/skill_editor/`、`tests/` 下 `.gd` 串行循环）。
  实测价值：CLI 报错常只覆盖它自己发现的文件，全量自检一次多揪出 2 个同类错误（plugin.gd、test_editor_ui.gd）。

### D-17 引擎执行权归 WorkBuddy 独占（2026-10-18）

- **决策**：Claude CLI 在并行批次中**不调用任何 godot 命令**，只写代码 + 写测试 + 静态语法复核；由 WorkBuddy 串行跑门禁并把**原始输出**回传给对应线修复。
- **理由**：多路 CLI 并发起 Godot 进程会争抢 `.godot/` 缓存（D-15 崩溃根因）。收回执行权后，CLI 可满速写代码、并行度最高，且引擎始终只有一个进程。
- **配套**：CLI 回执必须写「自测声明：未运行引擎，已静态复核」；**写"已通过"而未跑过 = 伪造门禁结果，直接 REJECT**（协议硬门禁第 3 条）。

### D-18 GDScript 静态复核点：`:=` 对 Variant 推断失败（2026-10-18 血案）

- **现象**：`var normalized := entry.duplicate(true)`，其中 `entry` 来自 `entries[index]`（无类型 Variant）→ `Parse Error: Cannot infer the type` → **整脚本编译失败** → 依赖它的测试全部报 `Nonexistent function 'new' in base 'GDScript'`，4 个用例全挂。
- **决策**：凡从 `Array`/`Dictionary` 取出的元素、或 `.duplicate()` / `.get()` 的返回值，一律写**显式类型**（`var x: Dictionary = ...`），禁止用 `:=`。
- **成本提示**：这类错误不是单点失败，是**整脚本连带失败**，静态复核必须优先扫这一项。

### D-09 `purge` 静默

- **决策**：清场不发 vanish、不派生、不补 hit；预算拒绝创建时实例从未存在，也不发补偿性消失（真源 4.9.3）。

### D-10 覆盖寻址用 `brick_index`〔解决真源未决项 U-04〕

- **缺口**：真源 3.3 / U-04 指出「同种积木在一个技能中出现多次时，仅用 `brick_id` 定位可能不够」，列为接口未决项；14.2 V-015 已出现 `params.brick_overrides[i].brick_index`。
- **决策**：采用 `params.brick_overrides[i].brick_index` 索引本文件 `bricks[]` 下标；`brick_id` 只作人类可读冗余与一致性校验，不作寻址主键。索引重复或越界 → V-015。
- **边界**：不写死同种积木数量上限；`brick_index` 指向的卡 `brick_id` 与覆盖项声明不一致时报错，不静默接受。

### D-11 载体四类以主书稿为准〔解决真源未决项 U-01〕

- **缺口**：共享文件用 `instant`，主书稿用 `self`，两边都有 `none`。
- **决策**：一律用 `none / self / independent / attached`；**导入时遇到 `instant` 直接拒收**，不静默迁移（真源卷三第 0 节同旨）。

### D-12 表现严格只读

- **决策**：表现只消费 `hit` / `hit_settled`；动画回调不得驱动出手/接触/脉冲/落地；对齐项必须同时有 `shot_tick` 与 `frame`。

### D-13 本期不接性能基线

- **决策**：100 子弹 / 80 特效 / 80 角色同屏属项目层验收，M4 只做「预算账本与拒绝原因可定位」（V-055/056/080），不做性能压测。

### D-14 提交纪律
