## 二、技术坑

| 编号 | 现象 | 根因 | 修法 / 防坑规则 |
|---|---|---|---|
| **P-01** | `Function "queue_redraw()" not found in base self` | `CanvasLayer` 属于 Node 分支，**不是 CanvasItem**，没有 `_draw()` / `queue_redraw()` | 分层交给 `CanvasLayer`，绘制脚本必须挂在 `Control` / `Node2D` 子节点上 |
| **P-02** | 投射物全部从屏幕左上角出生、贴着顶边飞 | `_exec_projectile` 先设 `global_position`，随后 `setup()` 内部 `position = Vector2.ZERO` 把它抹掉 | 构造/初始化函数**不要碰 transform**；位置由生成方在 `setup()` 之后赋值 |
| **P-03** | 命中时报 `Invalid access to property 'stats' on HurtboxComponent` | `HitboxComponent.strike(hurtbox, rng, defender)` 的第三参不可省；不传会退回用 hurtbox 当 defender，而 hurtbox 没有 `.stats` | 所有命中调用统一传「带 `.stats` 的实体本身」，不要传 hurtbox |
| **P-04** | 修好出生点后子弹瞬间消失、打不到木桩 | 出生点与施法者身体重叠，命中判定把自己算进目标 | `SandboxProjectile.attacker` 记录发射者，tick 里跳过；目标列表也别盲目传全部实体 |
| **P-05** | headless 探针无任何输出、进程被 SIGTERM 挂死 | 探针脚本弱类型变量用 `:=` 无法推断类型 → Parse Error → 场景永不 `quit()` | 探针一律写显式类型（`var ok: bool = ...`），并给 `--quit-after N` 兜底 |
| **P-06** | 面板里改了 `behavior_overrides` 却看不到效果 | key 与行为层实际 `params.get()` 的键不一致；或误用内部规范化键 | override 的 key 必须是行为层真实读取的键（`speed/pierce/chain_count/...`）；`projectile_count` 的 base 载体是内部键 `count_base`，报告里要隐藏、配置里别手写 |
| **P-07** | 整组装配失败时，用户看不出「哪颗没生效」 | 旧显示只有一个几乎不可见的 `·` | 逐项状态必须显式三态：`✓ 生效` / `✗ 问题源（原因）` / `○ 本身兼容但被拖累`；把「被拖累」和「不兼容」分开表达 |
| **P-08** | 新增 `class_name` 脚本后，headless 测试报 `Could not find type "Xxx"` | 全局脚本类缓存在 `.godot/`，只有编辑器导入时刷新，纯 headless 运行不会更新 | 新增/改名 `class_name` 后先跑 `godot --headless --path . --import` 刷新缓存，再跑测试 |
| **P-09** | `ProjectileSlot` 没有 `index` 字段，SoA 容器 `spawn()` 里 `slot.index` 直接崩 | 池原本只服务「一个 Node 一个槽」，槽位不需要知道自己在哪个数组里；改成 SoA 后必须知道 | `ProjectileSlot.index` 在**创建时钉死**（`_slots.size()`），回收复用不改变下标 |
| **P-10** | 测试跑完报 `824 ObjectDB instances leaked` | 假目标与假 hurtbox **互相引用**（`hurtbox.owner = target`），RefCounted 不回收引用环 | 鸭子类型假体只做**单向**引用；需要反查就通过断言侧聚合（`damage_taken()` 现算），别让假体之间成环 |
| **P-11** | 全量测试报 `Orphans 54` + `P11GodotArea2D leaked` | `SandboxEntity._init` 里 `new()` 了 `HurtboxComponent` 却**从未 `add_child`**，注释写了「在 _init 挂树」但代码没挂 | 注释写着「挂树」就一定要有 `add_child`；测完看 `Orphans` 计数，非 0 就是有节点没进树 |
| **P-12** | `assert_ge` / `assert_le` 在 GUT 9 里不存在，脚本 Parse Error | GUT 的命名是 `assert_gte` / `assert_lte` | 写断言前先确认 GUT 版本的方法名；`assert_gt/lt` 有，`ge/le` 没有 |

## 三、验证习惯

- 改沙盒表现 → 用 windowed 探针截图（`get_viewport().get_texture().get_image().save_png()`），headless 看不到画面。
- 改装配/数值 → 至少跑 `test_s_sandbox_smoke.gd` + `test_s_support_pool.gd`，提交前跑全量 `-gdir=res://mods/jes-skills/tests -ginclude_subdirs`。
- 新增辅助石 → 先问「改了几个 `.gd`」，答案必须是 0；改了就说明把策略写进代码了。
- 新增属性 → 同样问「改了几个 `.gd`」，答案必须是 1（只动 `util/stat_registry.gd` 的 `DEFS`）。
- 改了 stats / 装配 / 缓存 → 必跑 `test_stats_dirty_cache.gd` + `test_m3_assembly_cache.gd`；这两处出错的表现是"数值差一点点"，肉眼看沙盒看不出来。
- 跑渲染压测 → **不能用 headless**：`godot --path . --script res://mods/jes-skills/tests/perf/bench_render.gd`，先确认 `DisplayServer.get_name() != "headless"`，否则读数作废。
