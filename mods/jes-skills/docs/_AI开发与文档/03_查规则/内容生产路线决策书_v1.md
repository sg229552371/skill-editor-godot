# 内容生产路线决策书 v1（R10 解冻备料）

> 2026-10-22 制作人统一准则下生成：扩展性+兼容性优先，先完整功能后完整体验，不为小功能阻塞整体进化。
> 本文档只备料，**不拍板**。拍板项见 §四。
> 事实证据由只读调研产出（2026-10-22），每条附路径。

## 一、核心事实（决定成本的关键）

1. **加载链路极薄**：`GemRegistry`（`systems/skills/data/gem_registry.gd`）纯静态懒加载，`DirAccess` 扫目录 + `load()` 每个 `.tres`。运行时对象就是 SkillData 资源本体。**只要产物仍是「同目录、文件名==id 的 .tres」，整条运行时链和 GemRegistry 一行都不用改。**
2. **门禁耦合面很小**：4 个快照/契约文件里只有 `test_content_contract.gd` 直接依赖固定路径（自扫目录 + 断言文件名==id）；其余三个走 GemRegistry，与生成方式无关。→ 三条路线的测试冲击都可控。
3. **behavior_params 无 schema**：键面散落三处（7 个 behavior 代码 + 手册 §1.1 + 契约测试 BEHAVIOR_COMMON 表）。任何批量路线都要先有一份「键 ↔ 列」映射真源，否则生成器就是在翻译三处方言。
4. **E-04《技能系统书 v1》未入库**（信息来源清单 L99/L111；规格 §16 警示：书 12245 行、已不可读）。**A/C 路线的映射依据只能来自 E-04（CFG 七键），E-04 不投放则 A/C 无从论证——这是三选一分析 v1 已指出的循环依赖。**
5. **构建期生成无先例**：仓库内无 `@tool`/EditorScript；已有 `gen_content_snapshot.gd`（`-s` SceneTree headless 写文件）证明命令行脚本可跑可写，但「headless 里 `ResourceSaver.save` 落 .tres」无仓库内证据，路线 A 需先做一次 10 分钟可行性试刀。
6. **B 是既成事实**：67+13 个 .tres、契约层、快照全部以「手写 .tres 为唯一数据契约」建成。选 B = 追认，零迁移；选 A/C = 内容侧迁移。

## 二、三路线改动面对照（调研汇总）

| 维度 | A：CSV→构建期生成 | B：手写 .tres + 辅助脚本 | C：双轨适配层 |
|---|---|---|---|
| 运行时代码 | 不动 | 不动 | 不动（若适配层只做生成） |
| 400 个测试 | 全不动（产物守同路径同名） | 全不动 | 全不动 + 新增漂移门禁 |
| 新建 | CSV 表、生成脚本、列↔键映射文档 | 可选脚手架脚本 | 适配层 + 漂移检查 + 映射表 |
| 文档 | 手册 §6 重写 | 不动 | 新增双轨章节 |
| 前置依赖 | 10 分钟 ResourceSaver 试刀 | 无 | **E-04 投放（硬前置）** |
| 200 颗辅助时 | 最快（表编辑+一键生成） | 慢（逐个手写） | 快（同 A），但多养一层抽象 |
| 兼容性风险 | 低（产物形态不变） | 零 | 中（多一条数据路径要防漂移） |

## 三、与制作人准则的对齐

- **扩展性**：A 最优（策划表与引擎解耦，200+ 颗不痛）；C 灵活但复杂度最高；B 在内容量破百后成为效率瓶颈。
- **兼容性**：三者都保住 SkillData 运行时契约，261+ 用例基线全保。
- **敏捷/不为小功能阻塞整体进化**：B 是「什么都不做」，符合当下但不符合准则第 1 条的扩展性要求；A 是一次投入换长期效率；C 是在 A/B 之争未决时的对冲，代价是永久多一层维护。

## 四、需要制作人拍板的（按顺序）

- **Q1（路线）**：A / B / C 选哪条。
  - AI 意见（仅供参考，非结论）：若接受「先花半天做 A 的可行性试刀 + 键映射文档」，**A 长期最优**且与准则最契合；若想今天就开始铺量、把架构投入推迟，**B + 脚手架**是零风险过渡，且 B 产物未来可直接被 A 的生成器替换（因为契约就是 .tres 本身）——即 **B→A 是无损升级路径**，反过来不成立。
- **Q2（E-04）**：是否投放《技能系统书 v1》（12245 行外部文档，投 `docs/_重要资料记录/人工资料源/` 并登记）。选 A 或 C 必投；选 B 可暂缓。
- **Q3（铺量顺序）**：路线定稿后先铺主动（67→✅ 格补全）还是先铺辅助（13→几十）。参考：辅助缺口比例更大（13/200），且辅助全走 4 个口子、无行为新增，更适合当 A 路线首个批量试点。
