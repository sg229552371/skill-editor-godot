## 0. 三十秒说明

你（AI）在这个体系下做三类事，**对应三个不允许混淆的产物**：

| 任务 | 产物 | 依据章节 |
|---|---|---|
| 新增主动技能内容 | `content/gems/active/*.tres` | §3、§5 |
| 实装新的行为名称格（新行为能力） | 形状模块 / 新行为 `.gd` + 注册 + 测试 | §2 |
| 实现抽取玩法 | 抽取表数据结构 + 兼容判定接线 | §6 |

**三条总禁令**（违反即返工，与手册 §0 一致）：
1. 不用任何 PoE 技能名 / 图标 / 数值；
2. 不为单个技能改 `.gd`（策略进数据表）；
3. 不发明字段 / 标签 / 行为（不在注册表的名字 = 静默不生效）。

## 1. 行为名称模型：轴值与现有行为的映射

四轴冻结：投送 6 × 形状 7 × 时序 4 × 辅助类别 2。**已实现的 7 个行为只覆盖白名单中 12 格**（全矩阵展开见《02_行为名称全集_白名单矩阵_v1》）；轴组合 → 现有 `behavior_id` 的映射关系如下（AI 落内容时按此选行为，不要自创新行为）：

| 已实现格（投送×形状×时序） | `behavior_id` | 关键参数 |
|---|---|---|
| FLY × PT × S1 | `bhv_projectile` | `speed`/`radius`/`lifetime` |
| FLY × PT × TICK（穿透） | `bhv_projectile` | `pierce`=命中数−1（3 次=4 目标） |
| FLY × MULTI × S1（散射） | `bhv_projectile` | `count_base` / `spread_deg`（发数键**只认 `count_base`**） |
| FLY × CIRC × S1 | `bhv_projectile`（大半径）或双 part | 见手册 A4 边界说明 |
| INST × CIRC × S1 / DLY | `bhv_aoe_burst` | `radius` / `delay` |
| INST × CIRC × TICK（多段圈） | `bhv_aoe_burst` | `hit_count` / `hit_interval` |
| INST × SEC × S1 | `bhv_melee_swing` | `range` / `arc_deg` |
| CHAN × LINE × TICK | `bhv_channel` | `max_channel_time` / `tick_interval` |
| DASH × LINE × S1 | `bhv_dash` | `distance` / `speed`（`path_damage` 存在即启用） |
| SELF × SELF × S1 | `bhv_buff_self` | `buff_mods` / `duration` |
| SUMN × PT × S1+ZONE | `bhv_summon` | `max_count`（顶掉最旧语义，非批量召唤）/ `lifetime` |

**待实装格（P1 八格）需要的引擎改动**（动工前须经制作人确认，见总纲 §9#8）：

| 格 | 需要什么 | 备注 |
|---|---|---|
| INST × RING × *（空心冲击波等） | 形状模块：`RING` 判定 + 新参数 `inner_radius` | 形状模块是全部 RING/MULTI/ZONE 格的前提 |
| INST × LINE × S1（瞬发光束） | 形状模块：`LINE` 判定抽离 | 现有线判定只在引导与冲刺里 |
| INST × SEC × TICK（三段连斩） | 近战多段（现近战单段） | 参数即可，改动小 |
| CHAN × CIRC/SEC × TICK | 引导形状扩展 | 引导现仅直线 |
| DASH × CIRC × *（冲撞/火径） | 位移判定扩展 | 路径即判定路径 |
| SUMN × RING/LINE/MULTI（环形召/召唤墙/多点召） | 生成位置分布参数 | `minion_count` + 分布 |
| FLY × * × ZONE（光墙/毒圈弹） | 持续区域判定 | 可先由 TICK 模拟 |

**废格（×）永久封禁**：SELF×非自身形状、SUMN×SEC、FLY/INST×自身形状、引导单段等——实现请求遇到废格直接拒绝并引用总纲 §3.2。

## 2. 施放层字段契约（`SkillData`，已核对）

```gdscript
gem_id: StringName            # = 文件名
display_name: String          # 中文名，词根表组合（手册 §5）
parts: Array[SkillPart]       # 部件绑定；多部件技能段序有意义（见 §5 断言）
tags: Array[StringName]       # 初生标签 = 四轴派生 + 元素；禁发未注册标签
cast_mode: int                # 0=ACTIVE, 1=TRIGGER_ONLY
base_cast_time: float         # 前摇，区间 0.35–1.2
cost_type: int                # 0=MANA, 1=LIFE, 2=ENERGY_SHIELD, 3=NONE
base_cost: float              # 耗蓝，区间 6–25
base_cooldown: float          # 冷却，0–8
max_charges: int              # 充能数（0=不使用）
charge_recharge_time: float   # 充能回复
level_scaling: GemLevelScaling # 平滑0.1 / 开荒0.16+8拐+0.04 / 成型0.04+10拐+0.2 / 封顶0.12+10拐+0
allowed_support_tags: Array[StringName]  # 技能级禁止标签挂点；空数组=接受全部
```

`SkillPart`：`damage_channel`（1=HIT 默认，2=DOT，4=AILMENT）、`base_damage`（字典，键=元素）、`damage_effectiveness`（0.6–1.4，**不是强度旋钮**）、`behavior_id`、`behavior_params`。

**每秒伤害不是字段**——设计表导出列 = 总伤 × 段数 ÷ (前摇 + 冷却)。

## 3. 标签实现契约（一切皆标签）

### 3.1 注册表即边界

- 标签 14 个（`TagRegistry.DEFS`）：元素 5（`physical/fire/cold/lightning/chaos`）+ 辅助类别 2（`attack/spell`）+ 形态 7（`melee/projectile/aoe/channel/movement/summon/buff`）。
- 一个技能 = 1 个辅助类别 + 0–2 元素 + 1–2 形态；≥4 个标签说明设计未收敛。
- 标签派生：初生（四轴+元素）→ 收敛（`add_tags`，封顶 2 轮）→ 特性（池抽项白名单）。**元素不是轴**。

### 3.2 兼容判定（现按技能级实现，切换条件见 §4）

```
判定顺序：先查 exclude_tags（命中任一即拒绝）→ 再查 require_tags（全部具备才通过）
独占组 conflicts_with 必须双向一致
```

### 3.3 部件级判定（已定稿，切换点明确）

- **现状**：兼容判定在技能级（`socket_graph` 读 `allowed_support_tags`）。
- **目标态**：标签按部件派生，判定在部件级；技能级标签只做展示聚合。
- **切换触发条件**：第一批「需要指定部件」的辅助宝石立项时。届时 `SkillPart` 需增加部件级标签来源（从 `behavior_id`/轴派生），判定入口从技能移到部件。
- **禁止**：在切换前发明第二种屏蔽机制；一切屏蔽走禁止标签。

## 4. 辅助宝石实现契约（`SupportGemData`，已核对）

```gdscript
require_tags / exclude_tags / add_tags    # 三元组；require 是"且"不是"或"
add_tags 必须配套 behavior_overrides 或参数，否则装配成功但表现不变
conflicts_with: 双向一致
cost_multiplier: 1.0                      # 所有增益型辅助必须有代价（抬耗/限标签/flags）
stat_modifiers: Array[ModifierSpec]       # source_id = support_id
behavior_overrides: Dictionary            # {&"projectile_count": {&"add": 2.0}} 形式
flags: Array[StringName]                  # &"cannot_crit" 等
```

效果只走四个口子：改数值（`stat_modifiers`）/ 改数量形态（`behavior_overrides`）/ 改兼容范围（标签三元组）/ 改施法模式（overrides 或 `TriggerData`）。口子 4（conditions）**暂缓**（D-15），不得自行接线。

## 5. 测试断言清单（新增内容/新格的验收底线）

内容批次（每批必做，摘自手册 §8.2 与第 2 批规划 §9）：

1. `git status -- '*.gd'` 改动数 = 0（纯内容批）；
2. 全部 tag / stat / behavior_id 在注册表中；
3. `behavior_params` 键全部为行为层真实读取键（拼错=静默失效）；
4. 数值落手册 §4.2 区间；单位化耗资与 DPS 极差（≤2.5 倍）两判据通过；
5. 内容数量断言同步更新并写明依据（P-23：禁止放宽为 `>=`）；
6. 批次去重断言：「行为×形状」组合不重复；一格一决策验收；
7. 特定段序断言：双部件技能的段序固化（例：先增益后召唤）；
8. 全量 GUT 回归绿（R22 实测基线 **261 用例 / 1749 断言**；历史文档里的 257/1734、257/1729 是门禁脚本 Parse Error 期间的统计，**以你实测为准**）。

新行为名称格实装（额外必做）：

9. 新形状判定有独立单元测试（边界：恰在内半径 / 恰在线宽 / 扇角端点）；
10. 头less 无孤儿节点、无 ObjectDB 泄漏；性能红线：逻辑 ≤0.5 ms/帧增量。

## 6. 抽取玩法实现契约（中期开工前有效）

- 抽取 = **三选一 + 可跳过**，禁止系统直发结果；稀有度权重 + 保底计数（连出普通递增稀有率，出稀有重置）；
- 池项入库前过「决策差异」检查：与已有任何池项站位决策相同则不入池；
- 池项带「强度预算」字段，抽取时按预算配平；
- 抽取结果必须过既有兼容判定（§3.2/§3.3），黑名单、条件门、装配缓存全部复用；
- 技能标签详情页显示派生标签 + 一次完整伤害公式预览。

## 7. 禁止事项汇总（全文最严条款，违反即返工）

1. 运行时代码出现任何 gem_id 分支；
2. `behavior_params` 写 `projectile_count`（只认 `count_base`）；
3. 用 `damage_effectiveness` 当强度旋钮配平；
4. DoT 类内容不写 `damage_channel`（通道隔离 G9 失效）；
5. 新辅助无代价（不抬耗/不限标签）；
6. `conflicts_with` 单向；
7. `max_count` 误解为批量召唤（语义=场上上限，顶掉最旧，HARD_CAP=64）；
8. 自行实现口子 4（conditions）或自建生成器 / CSV / lint（§16 暂缓令）；
9. 实装废格或为凑格子新增轴值（轴值冻结 v1）；
10. 在抽取玩法中系统直发结果（必须是三选一+可跳过）；
11. 面向用户的任何文案/表格出现未翻译英文标识符（用户英文不好，2026-10-20 明令）；
12. 为单个技能改 `.gd`。
