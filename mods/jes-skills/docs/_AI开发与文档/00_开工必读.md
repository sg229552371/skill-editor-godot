## 二之三、免费接口判据的真实漏洞（D-53 回馈，**优先级最高**）

**症状**：项目一直宣称「新增一颗技能/辅助宝石不改任何 `.gd`」。这句话在**生产代码层成立，在测试层不成立**。

现有内容测试里到处是这种写法：

```gdscript
assert_eq(registry.get_skill(&"fireball").cost, 12)   # ← 硬编码了具体 id
```

新增内容本身不用改 `.gd`，**但要让测试保持全绿就得改测试**——成本没消失，只是换了个地方付。
判据被绕过的方式不是"有人违规"，而是**验证判据的代码本身违反了判据**。

**怎么判断你有没有踩到**：写下一条内容断言时问自己——
「这个 id 是我主动选的，还是从内容目录遍历出来的？」
主动选的 → 你在为这一个 id 写测试，新增别的 id 时这条测试帮不上忙。

**正确形态**（背包模块 P3 门禁已验证可行，见 `mods/jes-inventory/tests/inventory/test_p3_free_interface.gd`）：

```gdscript
# 遍历目录，只断言「所有内容都满足的结构性事实」
for path in _all_tres("res://mods/jes-skills/content/gems/active"):
    var s := load(path) as SkillData
    assert_ne(s.behavior_id, &"", "%s 未声明行为" % path)
    assert_eq(s.validate().size(), 0, "%s 自检不通过" % path)
```

**具体数值**（某颗技能的耗蓝、某条数值曲线）应放到**独立的数据快照文件**里整批断言，
而不是散落在行为测试中当作"顺手验证一下"。

**这条不改的后果**：内容规模每翻一倍，测试改动的边际成本同步翻倍，
最终会逼出「把断言放宽成 `assert_gt(size, 0)`」这种自欺——那一刻免费接口判据就彻底失效了。

> 现状：**✅ 已整改（2026-10-22）**。落地两份新门禁：
> - `tests/skills/test_content_contract.gd`（11 用例）：遍历目录全量断言结构契约，**零硬编码 id**，自带 R-1 复发哨兵（test_z1）
> - `tests/skills/test_content_snapshot.gd` + `content_snapshot.json`（2 用例）：80 条内容数值冻结，改数值必须重跑 `gen_content_snapshot.gd` 留痕
> - 三次反向注入验证：删必填参数红 / 契约里写 id 字面量红 / 静默改数值红
> 存量批次测试（P1/batch2/batchC）保留——它们验「批次交付完整性」，与契约层互补不冲突。
> **新写内容断言时**：结构走契约层自动覆盖，**不要**在新测试里写内容 id 字面量。

## 四、五条红线（违反即返工，这五条挡掉 80% 的架构腐化）

1. **术语只有一个：辅助宝石。** 项目内不存在「水晶」；旧文档里的"水晶"一律读作辅助宝石。
   另：原「粒子」→ **行为名称**；原「流派归属」→ **辅助类别**。两个旧词已废止（制作人裁定）。
2. **辅助宝石不得替换 `SkillData` 引用本身**（禁止出现 `active_gem` 之类字段）。
   要"技能变身" = 装备层换 `slot.active_gem`，不是辅助宝石的事。
3. **辅助宝石只有四个作用口子**：`stat_modifiers` / `add_tags` / `behavior_overrides` / `conditions`。
   前三个已可用；**第四个（`conditions`）暂缓实现（D-15）**。不要因为"架构看起来缺一块"就自行接上——
   真需要时按规格 §6.3 的 4 步做，**顺序不许变**。
4. **通道必须隔离**：不得让点燃/中毒吃 hit damage 词缀（`Channel{HIT,DOT,AILMENT}` 位掩码）。
5. **不得合并 `Channel` 位掩码、不得退回"分系伤害"、不得去掉 `add_tags` 多轮收敛**。
   这三条是**修过的 bug**，不是口味问题。理由见 `项目记忆图谱` N03。

## 十、给人类的三条使用建议

1. **一次只给一个里程碑**，通过后再给下一个，否则 AI 会为了"看起来完整"而跨越门禁。
2. **每次 review 只看两件事**：① 有没有写死的宝石 id / 数值；② 新增一个辅助石需要改几个 `.gd`（**应为 0**）。
