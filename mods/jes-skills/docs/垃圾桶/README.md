# 垃圾桶（不是删除区，是"待复核的冷存区"）

> 建立：2026-10-21 R23，人类指令「AI 判断，无用或过时文件移除到垃圾桶文件夹；
> 但**任务目标与任务完成类的文件不算过时**，不要动」。

## 一、这里放什么

| 放进来 ✅ | 不放进来 ❌ |
|---|---|
| **内容已被吸收**：结论已并入现行口径，原文只剩过程 | **任务目标**：待拍板的规划、待裁定的提案（哪怕搁置很久） |
| **描述的对象已不存在**：所指文件/目录/规则已被删除或改名 | **任务完成记录**：进度表、验收结论、里程碑 |
| **已作废但需留痕**：写错了的、被裁定推翻的，删了会丢证据 | 冻结证据（无论多旧） |
| **重复的旧版**（新版已就位） | 过程稿（D-19：演进留痕，保持原样） |

## 二、为什么不直接删

1. **AI 判断会错**。误删人类投放物/证据无法用 git 之外的手段挽回，而误移可一键还原。
2. **"过时"是有时效的判断**。今天的过时可能是明天的追溯线索（例：被推翻的方案，恰恰解释了现行规则为什么长这样）。
3. **人类 review 成本最低**：垃圾桶里就那么几份，看一眼就能拍板"删/留"。

## 三、怎么用

- **AI**：发现符合上表左侧的文件 → `git mv` 到这里 → 在本文件 §四 登记一行 → 同步修正所有引用。
  **不得**把文件直接删掉，**也不得**因为"看起来旧"就丢任务目标/任务完成类文件。
- **人类**：定期清空。彻底删除前建议 `git log -- <文件>` 确认没有未吸收的结论。
