## 五、这个模块存在的理由

**它不是「又做一套东西」，而是判据实验。**

技能系统的治理机制（单真源、声明面、反向注入、改动回写、免费接口）是否真的通用？
只在技能系统上成立不算通用。本模块用一次**真实的、不同类型的实现**（背包 vs 技能）去检验：

| 判据 | 在背包系统上的检验点 | 实测 |
|---|---|---|
| 单真源 | 格子口径（5×6 / 5×7）只能有一处定义 | ✅ 但要区分「真源」与「派生量」 |
| 声明面 | 物品自己声明占几格、能不能叠，由机器核对 | ✅ 且比技能系统更强（链路短） |
| 免费接口 | 新增一种物品不需要改任何 `.gd` | ✅ 前提是测试不许硬编码 id |
| 反向注入 | 每个门禁必须被证明能红一次 | ✅ 已做 3 次，全部变红 |
| 改动回写 | 改了什么必须回写固定清单 | ⚠️ 复杂度未达阈值，未启用 |

**详细论证、注入记录、对技能系统的回馈** → `判据复刻实验报告_v1.md`（本模块核心资产）
